Kosaraju's Algorithm

The Advanced Masterclass: Pushing SCCs to the Absolute Limit

Welcome to the deep end. You already know the basics: Step 1: DFS and push to stack on exit. Step 2: Reverse the graph. Step 3: Pop from stack and run DFS to find Strongly Connected Components (SCCs).

But why does it work? What is the secret geometry of graphs that makes this 3-step dance so flawless? And more importantly, how do we weaponize this algorithm to solve some of the hardest problems in computer science? Let's dive in.

1. The Secret Sauce: Why It Actually Works

To understand Kosaraju deeply, you need to understand the Condensation Graph. Imagine you take every SCC in a graph, wrap it in a bubble, and treat that whole bubble as a single giant "Super-Node". If you draw edges between these Super-Nodes based on the original edges, you get the Condensation Graph.

The Condensation Graph of ANY directed graph is ALWAYS a Directed Acyclic Graph (DAG). There are no cycles between SCCs. If there were a cycle between two SCCs, they would merge and become one giant SCC!

Now, here is the absolute genius of Kosaraju's algorithm:

  • The First DFS: When you run the first DFS and push nodes to a stack upon exiting, you are actually sorting the SCCs! The node sitting at the top of the stack is guaranteed to belong to a "Source SCC" (an SCC with no incoming edges from other SCCs in the Condensation Graph).
  • The Bleeding Problem: If we just ran DFS from that Source SCC right away, we would "bleed" into all the other downstream SCCs. We wouldn't know where our SCC ends and the next one begins.
  • The Reversal (The Magic): When we transpose (reverse) all edges, the DAG is inverted. The Source SCC becomes a Sink SCC (no outgoing edges). Now, when we pop that node from the stack and run DFS on the reversed graph, it is physically trapped! It can visit every node in its own SCC, but it cannot bleed into other SCCs because the exit doors are now entrance doors!

2. Real-World Industry Usage

You might wonder, "Is this just a competitive programming trick?" Absolutely not. SCCs are foundational to how the modern world processes complex networks.

Social Network Echo Chambers

Twitter (X) and Facebook use SCCs to identify "Echo Chambers" or highly insular communities. If a massive group of users all mutually follow each other (creating an SCC), algorithms can classify them as a tightly-knit sub-community for targeted advertising or trend analysis.

Package Managers (npm, pip)

When installing software dependencies, circular dependencies can crash the build. Package managers use SCC detection to identify packages that depend on each other in a loop, grouping them together so the compiler can process them as a single monolithic unit.

Google Maps & GPS Routing

Imagine driving into a neighborhood of one-way streets where you can't get out. That's a "Sink SCC". Map routing algorithms pre-process city grids using Kosaraju's to ensure that every zone is reachable and, crucially, that drivers can escape back to the main highway network.

3. The God-Tier Patterns (Variations)

Once you extract the SCCs, you unlock a new tier of problem-solving. Here are the three main patterns you will see in high-level interviews and CP.

Pattern 1: DAG-ification + Dynamic Programming

The Setup: You are given a graph with values on nodes. You want to find a path that maximizes the sum of values, and you can visit nodes multiple times (but you only collect the value once).

The Play: 1. Use Kosaraju to find all SCCs. 2. Shrink each SCC into a single Super-Node. The value of the Super-Node is the sum of all nodes inside it. 3. Build the Condensation Graph (which is a DAG). 4. Run a simple DP or Topological Sort on the DAG to find the longest path. What was a wildly complex cyclic graph is now a trivial DP-on-DAG problem!

Pattern 2: 2-SAT (2-Satisfiability)

The Setup: You have boolean constraints like: "Either Alice comes to the party OR Bob comes" (A || B), and you have thousands of these. Is there a valid guest list?

The Play: Convert A || B into implications: !A → B and !B → A. Build a directed graph from these.

Run Kosaraju's. If any variable X and its negation !X belong to the same SCC, it's a paradox! The system is unsolvable. If they are in different SCCs, a valid assignment is guaranteed to exist!

Pattern 3: The Minimum Edges to Strongly Connect

The Setup: "What is the minimum number of new one-way roads we need to build so that every city can reach every other city?"

The Play: Find the SCCs and build the Condensation Graph. Count how many Super-Nodes have an in-degree of 0 (let's call it in0) and how many have an out-degree of 0 (let's call it out0).

The minimum edges required to make the whole graph strongly connected is exactly max(in0, out0) (except when the graph is already one SCC, then answer is 0). You literally just connect the sinks to the sources!

4. Destroying the Example Problem: Planets and Kingdoms

CSES Problem: A game has n planets, connected by m teleporters. Two planets a and b belong to the same kingdom exactly when there is a route both from a to b and from b to a. Determine for each planet its kingdom.

This is the purest form of Kosaraju's Algorithm. "Mutual reachability" is the exact definition of an SCC. A "Kingdom" is an SCC. We need to assign an ID to each SCC.

#include <bits/stdc++.h>
using namespace std;

const int MAXN = 100005;
vector<int> adj[MAXN], rev_adj[MAXN];
bool visited[MAXN];
stack<int> st;
int kingdom[MAXN]; // Stores the kingdom ID for each planet

// Step 1: Normal DFS to fill the stack with exit times
void dfs1(int u) {
    visited[u] = true;
    for (int v : adj[u]) {
        if (!visited[v]) dfs1(v);
    }
    st.push(u); // Push on exit!
}

// Step 3: DFS on reversed graph to map SCCs
void dfs2(int u, int id) {
    visited[u] = true;
    kingdom[u] = id; // Assign planet 'u' to kingdom 'id'
    for (int v : rev_adj[u]) {
        if (!visited[v]) dfs2(v, id);
    }
}

int main() {
    int n, m;
    cin >> n >> m;
    
    for (int i = 0; i < m; i++) {
        int u, v; cin >> u >> v;
        adj[u].push_back(v);
        rev_adj[v].push_back(u); // Build reversed graph immediately
    }
    
    // Pass 1
    memset(visited, false, sizeof(visited));
    for (int i = 1; i <= n; i++) {
        if (!visited[i]) dfs1(i);
    }
    
    // Pass 2
    memset(visited, false, sizeof(visited));
    int current_kingdom_id = 0;
    
    while (!st.empty()) {
        int u = st.top();
        st.pop();
        if (!visited[u]) {
            current_kingdom_id++; // Found a new SCC!
            dfs2(u, current_kingdom_id);
        }
    }
    
    // Output format exactly as requested by CSES
    cout << current_kingdom_id << "
";
    for (int i = 1; i <= n; i++) {
        cout << kingdom[i] << (i == n ? "" : " ");
    }
    cout << "
";
    
    return 0;
}
