STATUS: MAPPING GALAXY · GRAPH THEORY · KOSARAJU'S ALGORITHM

Not just "is it one kingdom" — what are ALL the kingdoms?

n planets, m one-way teleporters. Two planets share a kingdom exactly when they can reach each other. This time we don't just want yes/no — we want the entire map, labeled, kingdom by kingdom.

The problem, restated as a transmission manifest

// input n planets, m one-way teleporters (a → b) // output k number of kingdoms label[1..n] kingdom id (1..k) for every planet

Quick recap, in one line: earlier we checked whether an entire graph is one strongly connected blob, using two BFS runs from a single hub. That trick only answers yes/no. Here we go further — we'll find every blob, however many there are, and label every node. This is the full Kosaraju's algorithm.

The mechanism

Two passes: explore, then flood-fill in reverse

Think of each planet as a room. You walk in, and while you're inside, you visit every room reachable from it before you're allowed to "leave." The moment you finish visiting everything reachable from a room — that's its finish time. Kosaraju's algorithm is built entirely around comparing finish times.

Pass 1 — Explore & stack

Run a DFS across the original teleporter graph. Every time you finish exploring everything reachable from a planet, push that planet onto a stack. Planets that take longest to "close out" — because huge chunks of the galaxy hang off them — end up near the top.

Pass 2 — Pop & flood-fill in reverse

Flip every teleporter's direction. Pop planets off the stack one at a time. If a planet hasn't been claimed by a kingdom yet, everything you can reach from it on this reversed map is exactly one full kingdom. Color it, move to the next unclaimed planet on the stack, repeat.

The proof

Why popping in reverse-finish order carves out exact kingdoms

This is the part that genuinely surprises people the first time they see it. It hinges on one lemma about finish times.

01

Collapse each kingdom into one supernode.

Squash every planet in a kingdom into a single blob. The result — the condensation — is guaranteed to be a DAG (a graph with no cycles between kingdoms). Why? If two kingdom-blobs pointed to each other, they'd actually be mutually reachable — meaning they were never two separate kingdoms to begin with.

02

The finish-time lemma.

For any two kingdoms A and B, if there's a teleporter route from A's blob to B's blob in the condensation, then the highest finish time inside A is always greater than the highest finish time inside B — no matter which planet you start the DFS from.

03

Why the lemma is true.

Whichever kingdom the DFS stumbles into first, one of two things happens. If it enters A first: since A can reach B, that same DFS call will tunnel through and finish all of B before it can finish A's starting planet — so A's finish times end up higher. If it enters B first: since B can't reach back to A (the condensation has no A←B edge, or that would form a cycle), the DFS finishes all of B and closes it out completely before A is even touched — so again, A's finish times end up higher, just later in time.

04

So the very last planet to finish belongs to a "source" kingdom.

A kingdom with no incoming teleporters from any other kingdom. Nothing in the condensation points to it.

05

Flip the map, and that source kingdom becomes a dead end.

On the reversed teleporter graph, a kingdom with no incoming routes becomes a kingdom with no outgoing routes. So starting a search from the top-of-stack planet on the reversed map can only wander around inside its own kingdom — it's fenced in. It can never leak into a different kingdom.

06

Repeat, and every leak is fenced off in turn.

Pop the next unclaimed planet from the stack, flood-fill on the reversed map again — same argument applies, because once a kingdom's planets are all claimed, the remaining unclaimed planets are always the newest "topmost" source kingdom of what's left. One clean kingdom, every single time.

Zoom out

The condensation: your galaxy, minus the tangles

Once every kingdom is found, you can shrink each one down to a single point. Whatever tangled mess of teleporters existed inside a kingdom disappears — what's left between kingdoms is always a clean DAG.

This is the payoff: once you're looking at a DAG, every DAG-only trick becomes available — topological sort, dynamic programming over dependencies, longest paths, counting reachable pairs — even though the original graph was full of cycles.

Implementation

Iterative, two-pass, no recursion

Same reason as before: at n = 100,000, a recursive DFS risks a stack overflow on a long chain of planets. Both passes below are written with explicit stacks.

// CSES 1683 - Planets and Kingdoms
#include <bits/stdc++.h>
using namespace std;

int n, m;
vector<int> adj[100001], radj[100001];
bool visited_[100001];
int comp[100001];
vector<int> order_;

int main(){
    ios_base::sync_with_stdio(false); cin.tie(nullptr);
    cin >> n >> m;
    for (int i = 0; i < m; i++){
        int a, b; cin >> a >> b;
        adj[a].push_back(b);
        radj[b].push_back(a);
    }

    // Pass 1: iterative DFS, record finish order
    vector<int> itIdx(n + 1, 0);
    for (int s = 1; s <= n; s++){
        if (visited_[s]) continue;
        vector<int> stk{s};
        visited_[s] = true;
        while (!stk.empty()){
            int u = stk.back();
            if (itIdx[u] < (int)adj[u].size()){
                int v = adj[u][itIdx[u]++];
                if (!visited_[v]){ visited_[v] = true; stk.push_back(v); }
            } else {
                order_.push_back(u);
                stk.pop_back();
            }
        }
    }

    // Pass 2: pop in reverse finish order, flood-fill on the reversed graph
    int k = 0;
    for (int i = (int)order_.size() - 1; i >= 0; i--){
        int s = order_[i];
        if (comp[s] != 0) continue;
        k++;
        vector<int> stk{s};
        comp[s] = k;
        while (!stk.empty()){
            int u = stk.back(); stk.pop_back();
            for (int v : radj[u])
                if (comp[v] == 0){ comp[v] = k; stk.push_back(v); }
        }
    }

    cout << k << "\n";
    for (int i = 1; i <= n; i++) cout << comp[i] << " \n"[i == n];
}
# CSES 1683 - Planets and Kingdoms
import sys

def main():
    data = sys.stdin.buffer.read().split()
    idx = 0
    n = int(data[idx]); idx += 1
    m = int(data[idx]); idx += 1

    adj  = [[] for _ in range(n + 1)]
    radj = [[] for _ in range(n + 1)]
    for _ in range(m):
        a = int(data[idx]); idx += 1
        b = int(data[idx]); idx += 1
        adj[a].append(b)
        radj[b].append(a)

    visited = [False] * (n + 1)
    it_idx  = [0] * (n + 1)
    order = []

    # Pass 1: iterative DFS, record finish order
    for s in range(1, n + 1):
        if visited[s]:
            continue
        stack = [s]
        visited[s] = True
        while stack:
            u = stack[-1]
            if it_idx[u] < len(adj[u]):
                v = adj[u][it_idx[u]]
                it_idx[u] += 1
                if not visited[v]:
                    visited[v] = True
                    stack.append(v)
            else:
                order.append(u)
                stack.pop()

    # Pass 2: pop in reverse finish order, flood-fill on the reversed graph
    comp = [0] * (n + 1)
    k = 0
    for s in reversed(order):
        if comp[s] != 0:
            continue
        k += 1
        stack = [s]
        comp[s] = k
        while stack:
            u = stack.pop()
            for v in radj[u]:
                if comp[v] == 0:
                    comp[v] = k
                    stack.append(v)

    out = [str(k), ' '.join(str(comp[i]) for i in range(1, n + 1))]
    print('\n'.join(out))

main()

Both run in O(n + m) time and space — two linear passes, not one per node. n = 1 or a graph with zero teleporters both work fine: every planet is its own kingdom.

Where this actually gets used

Real applications, not just contest problems

2-SAT solving

Given a boolean formula where every clause has exactly two literals, build an "implication graph": each literal points to whatever it forces to be true. Run Kosaraju. If a variable and its negation ever land in the same SCC, the formula is unsatisfiable — full stop, no backtracking search needed. This turns a problem that looks like it needs brute-force SAT solving into a linear-time graph algorithm.

Circular dependency detection

Build systems and package managers model modules as a directed graph of "depends on" edges. Any SCC of size greater than one is a circular dependency — module A needs B, which eventually needs A back. Compilers and dependency resolvers use exactly this to reject broken build graphs before wasting time compiling.

Mapping the shape of the web

In the landmark 2000 study "Graph Structure in the Web," Broder et al. computed SCCs across hundreds of millions of pages and found the web has a "bowtie" shape: a giant central SCC (pages that can all reach each other), an IN region feeding into it, an OUT region it feeds into, and disconnected tendrils — all discovered by running exactly this kind of algorithm at massive scale.

Feedback-loop detection in circuits

Model a digital circuit's signal dependencies as a directed graph. A purely combinational circuit's graph should be acyclic. If SCC analysis finds a cycle, that's a feedback loop — meaning the design needs a register or latch to handle state, not plain combinational logic. EDA (electronic design automation) tools run this kind of check as a matter of course.

Beyond the basic problem

PatternWhat changes

Kosaraju vs. its single-pass cousins

AlgorithmPassesIdeaTrade-off
Kosaraju (1978)Two DFS passes + a reversed graphFinish-time ordering, then flood-fill in reverse.Easiest to prove correct; needs the reversed graph stored in memory.
Tarjan (1972)One DFS passTracks a "low-link" value per node to detect the root of each SCC on the fly, using one explicit stack.No reversed graph needed and typically faster in practice; the low-link invariant is trickier to prove and implement correctly.

Fun historical wrinkle: Tarjan's single-pass method actually predates Kosaraju's two-pass method by about six years — the "easier to understand" algorithm came later, not first.

Things that make this click

Facts worth remembering

01

The name has two owners

Kosaraju's algorithm is credited to S. Rao Kosaraju, who described it in an unpublished 1978 note — it was independently published by Micha Sharir in 1981, which is why some textbooks call it the Kosaraju–Sharir algorithm.

02

The condensation is always acyclic

No matter how tangled the original graph is, collapsing every SCC into a point always produces a DAG. This is what makes SCC-finding a gateway into every DAG algorithm — topological sort, DP, longest/shortest paths — for graphs that originally had cycles everywhere.

03

Two BFS from a hub is a special case of this

The earlier "is the whole graph one SCC" check is exactly what happens if you run Kosaraju's algorithm and get k = 1 at the end. Same machinery, one is just the yes/no shortcut.

04

2-SAT turns satisfiability into a graph problem

Deciding general boolean satisfiability is NP-complete. Restricting every clause to exactly two literals collapses that difficulty entirely — it becomes solvable in linear time purely because SCCs can be found in linear time.

05

Recursion is the silent killer here too

A textbook recursive version of Pass 1 (DFS, then push on the way back up the call stack) is elegant to write but will blow the call stack on a graph shaped like a single long chain of 100,000 planets. The iterative version above sidesteps that entirely.

06

Kingdoms can be a single planet

A planet with no teleporter cycles through it at all is still a perfectly valid kingdom — just a kingdom of one. Kosaraju's algorithm handles this with zero special-casing.
