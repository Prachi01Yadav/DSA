01

Quick Graph Refresher

Foundation · ~20 min

🗺️ Think of a city's road network

A graph is just a bunch of nodes (also called vertices) connected by edges. Picture Delhi: intersections are nodes, and roads between them are edges. If every road is one-way, it's a directed graph. If roads go both ways, it's undirected.

  • Each edge can have a weight — think of it as the time to travel that road.
  • The shortest path from A to B is the path with the lowest total weight.
  • In 0/1 BFS, every edge has weight either 0 or 1. Nothing else.
💡

Key insight: In the above graph, the best path from S to T is NOT the one with fewest edges. It's the one with lowest total weight. That's why we need a smart algorithm — not just counting hops.

02

Normal BFS — The Starting Point

Foundation · ~25 min

🚶 What BFS does (in plain English)

Normal BFS uses a queue and explores nodes level by level — first all neighbors at distance 1, then all at distance 2, and so on. This works perfectly when every edge has the same cost (like cost = 1).

Think of it like ripples in water. You drop a stone (start node). Ripples spread outward, all at the same speed, one ring at a time.

Here's the classic BFS for unweighted graphs:

JAVA Normal BFS — unweighted graph 
import java.util.*;

public class NormalBFS {

    // Graph represented as adjacency list
    static List<List<Integer>> graph;

    static int[] bfs(int start, int n) {
        int[] dist = new int[n];
        Arrays.fill(dist, Integer.MAX_VALUE);
        dist[start] = 0;

        Queue<Integer> queue = new LinkedList<>();
        queue.add(start);

        while (!queue.isEmpty()) {
            int node = queue.poll();   // Take from front

            for (int neighbor : graph.get(node)) {
                if (dist[neighbor] == Integer.MAX_VALUE) {
                    dist[neighbor] = dist[node] + 1;  // Every edge costs 1
                    queue.add(neighbor);
                }
            }
        }
        return dist;
    }
}
⚠️

The problem: Normal BFS assumes all edges cost exactly 1. The moment some edges cost 0 and others cost 1, BFS breaks — it can give wrong answers. That's where 0/1 BFS comes in.

03

The 0/1 BFS Idea — The "Aha" Moment

Foundation · ~30 min

🎟️ Real World Example: Delhi Metro with Free Transfers

Imagine you're navigating the Delhi Metro. Most legs of your journey cost ₹1 (one station to next). But at certain stations, there's a free transfer — you can switch lines or take a moving walkway for ₹0.

Your goal: reach Connaught Place from your home station with the minimum fare.

  • Normal edge → costs 1 (regular station hop)
  • Special edge → costs 0 (free transfer / walkway)

❓ Why does normal BFS fail here?

Normal BFS processes nodes in order of number of edges, not total cost. Suppose:

  • Path A → B takes 3 edges of cost 0 each → total cost = 0
  • Path A → C takes 1 edge of cost 1 → total cost = 1

Normal BFS would explore C before it fully explores B (because C is "closer" in edges). But B is actually cheaper! This gives wrong answers.

🧠

The key insight: When you take a 0-cost edge, you should be at the same "level" as before — you haven't paid anything extra. So the neighbor via a 0-edge should be processed before any 1-edge neighbors. This is the core trick.

🎯 The Rule in One Line

When moving to a neighbor:

  • If edge weight = 0 → add neighbor to the front of the deque (process it soon!)
  • If edge weight = 1 → add neighbor to the back of the deque (it's costlier, do later)

This keeps our deque sorted by cost automatically. No sorting needed. No priority queue. Just a deque!

04

The Deque Trick — How it Works

Core Mechanics · ~25 min

📦 What is a Deque?

A deque (double-ended queue) is like a queue, but you can add or remove from both ends. Think of it as a tube of chips — you can put chips in from either side and take them out from either side.

📌 Deque state after processing node A (dist=2):
FRONT
(pop here)
X
Y
B
C
D
BACK
(push 1-edges)

X and Y are 0-cost neighbors of A, pushed to front. B, C, D are 1-cost neighbors, pushed to back.

🔑 The invariant (fancy word, simple idea)

At any point, the deque only contains nodes with at most 2 different distances: the current minimum distance, and current + 1. All 0-cost neighbors stay at the same cost level, so they sit at the front. All 1-cost neighbors go to the back.

This means when we pop from the front, we always get the node with the smallest known distance — just like a priority queue, but faster and simpler!

1

Initialize

Set dist[start] = 0, dist[all others] = ∞. Add start to deque.

2

Pop from front

Take the node with smallest current distance from the front of the deque.

3

Check all neighbors

For each neighbor, compute: newDist = dist[current] + edge_weight (0 or 1).

4

Update if better

If newDist < dist[neighbor], update it. If edge was 0 → push to front. If edge was 1 → push to back.

5

Repeat until deque is empty

When the deque is empty, dist[] contains shortest distances from start to all nodes.

Step-by-Step Trace — Watch it Run

Core Mechanics · ~30 min

🎬 The Scenario: Shortest trip from 0 to 4

Here's a small graph. Edges marked with cost. Let's trace 0/1 BFS by hand.

📋 Trace table — every step

Step Pop node dist[] Deque after step Action
Start — [0, ∞, ∞, ∞, ∞] [0] Initialize, add node 0
1 0 [0, 1, 0, ∞, ∞] [2, 1] 0→1 (cost 1, back), 0→2 (cost 0, front)
2 2 [0, 1, 0, 1, ∞] [1, 3] 2→3 (cost 1, back). dist[1] already 1, no update.
3 1 [0, 1, 0, 1, ∞] [3] 1→3 (cost 0): newDist = 1+0 = 1 = dist[3], no improvement.
4 3 [0, 1, 0, 1, 2] [] 3→4 (cost 1): dist[4] = 1+1 = 2. Push to back.
5 4 [0, 1, 0, 1, 2] [] No unvisited neighbors. Done!

Shortest path from 0 to 4 = 2 (path: 0 → 2 → 3 → 4, cost = 0+1+1 = 2). Notice node 2 was put in front because it had a 0-cost edge, and was processed before node 1 even though we discovered both at step 1!

Full Java Code — The Template

Core Mechanics · ~35 min

This is the template you'll use for almost every 0/1 BFS problem. Read every comment carefully.

JAVA 0/1 BFS — Complete Template (Graph with edge weights 0 or 1) 
import java.util.*;

public class ZeroOneBFS {

    // Edge class to store neighbor and its weight (0 or 1)
    static class Edge {
        int to, weight;
        Edge(int to, int weight) {
            this.to = to;
            this.weight = weight;
        }
    }

    static int[] zeroOneBFS(List<List<Edge>> graph, int start, int n) {

        // dist[i] = shortest distance from 'start' to node i
        int[] dist = new int[n];
        Arrays.fill(dist, Integer.MAX_VALUE);
        dist[start] = 0;

        // Deque: double-ended queue. Acts like a queue but
        // lets us push to FRONT (for 0-cost edges)
        Deque<Integer> dq = new ArrayDeque<>();
        dq.addFirst(start);   // Add start to front (or back, doesn't matter)

        while (!dq.isEmpty()) {
            int node = dq.pollFirst();  // Always pop from front

            for (Edge edge : graph.get(node)) {
                int neighbor = edge.to;
                int newDist  = dist[node] + edge.weight;

                if (newDist < dist[neighbor]) {
                    dist[neighbor] = newDist;

                    if (edge.weight == 0) {
                        // Free edge! Push to FRONT — same cost level
                        dq.addFirst(neighbor);
                    } else {
                        // Costs 1. Push to BACK — higher cost level
                        dq.addLast(neighbor);
                    }
                }
            }
        }

        return dist;
    }

    public static void main(String[] args) {
        int n = 5;  // 5 nodes: 0, 1, 2, 3, 4
        List<List<Edge>> graph = new ArrayList<>();
        for (int i = 0; i < n; i++) graph.add(new ArrayList<>());

        // Add edges: (from, to, weight)
        graph.get(0).add(new Edge(1, 1));  // 0→1, cost 1
        graph.get(0).add(new Edge(2, 0));  // 0→2, cost 0 (free!)
        graph.get(1).add(new Edge(3, 0));  // 1→3, cost 0
        graph.get(2).add(new Edge(3, 1));  // 2→3, cost 1
        graph.get(3).add(new Edge(4, 1));  // 3→4, cost 1

        int[] dist = zeroOneBFS(graph, 0, n);

        for (int i = 0; i < n; i++) {
            System.out.println("dist[0→" + i + "] = " + dist[i]);
        }
        // Output:
        // dist[0→0] = 0
        // dist[0→1] = 1
        // dist[0→2] = 0
        // dist[0→3] = 1
        // dist[0→4] = 2
    }
}

📌 Key Java points to remember

  • Use ArrayDeque — it's faster than LinkedList in Java
  • addFirst() = push to front (for 0-cost edges)
  • addLast() = push to back (for 1-cost edges)
  • pollFirst() = pop from front (always)
  • Initialize dist[] with Integer.MAX_VALUE, not -1 (we compare with <)
  • You can re-add nodes to the deque if you find a shorter path — this is normal!
O(V + E) Time O(V + E) Space

V = number of nodes, E = number of edges. Same complexity as normal BFS — but handles 0/1 weights correctly.

Why Not Just Use Dijkstra?

Core Mechanics · ~15 min
Aspect0/1 BFSDijkstra
Time Complexity O(V + E) O((V + E) log V)
Data structure ArrayDeque (simple) PriorityQueue (heavier)
Edge weights Only 0 or 1 Any non-negative
Code complexity Simple More boilerplate
Competitive edge Faster in practice for 0/1 graphs General purpose
💡

The rule of thumb: If all edge weights are 0 or 1 — use 0/1 BFS. It's faster, simpler, and won't TLE where Dijkstra might. If weights are arbitrary non-negative integers — use Dijkstra.

Pattern #1 — Grid Problems

Patterns · ~35 min

🗺️ Real Example: Battlefield Navigation

You're controlling a soldier on a grid. '.' is an open field (free to walk through, cost 0 from edge to edge within open area). '#' is a wall — you can't go there. '*' is a minefield — you can cross but it costs 1 HP (treat as cost 1). Find minimum HP lost to reach the bottom-right corner from the top-left.

💡

Grid → Graph: Every cell is a node. Moving to an adjacent cell is an edge. The weight of that edge is 0 if the destination is safe, 1 if it's a minefield. This maps directly to 0/1 BFS!

JAVA 0/1 BFS on a Grid 
import java.util.*;

public class GridZeroOneBFS {

    static int[] dx = {0, 0, 1, -1};  // 4 directions
    static int[] dy = {1, -1, 0, 0};

    public static int minCost(char[][] grid) {
        int rows = grid.length;
        int cols = grid[0].length;

        int[][] dist = new int[rows][cols];
        for (int[] row : dist) Arrays.fill(row, Integer.MAX_VALUE);
        dist[0][0] = 0;

        Deque<int[]> dq = new ArrayDeque<>();
        dq.addFirst(new int[]{0, 0});

        while (!dq.isEmpty()) {
            int[] cur = dq.pollFirst();
            int r = cur[0], c = cur[1];

            for (int d = 0; d < 4; d++) {
                int nr = r + dx[d];
                int nc = c + dy[d];

                // Check bounds and avoid walls
                if (nr < 0 || nr >= rows || nc < 0 || nc >= cols) continue;
                if (grid[nr][nc] == '#') continue;

                // Minefield costs 1, open field costs 0
                int w = (grid[nr][nc] == '*') ? 1 : 0;
                int newDist = dist[r][c] + w;

                if (newDist < dist[nr][nc]) {
                    dist[nr][nc] = newDist;
                    if (w == 0) {
                        dq.addFirst(new int[]{nr, nc});  // Free! Front.
                    } else {
                        dq.addLast(new int[]{nr, nc});   // Cost 1. Back.
                    }
                }
            }
        }

        return dist[rows - 1][cols - 1];
    }

    public static void main(String[] args) {
        char[][] grid = {
            {'.', '.', '*'},
            {'*', '.', '.'},
            {'.', '*', '.'}
        };
        System.out.println(minCost(grid));  // Output: 0 (path exists with no mines)
    }
}

🔍 What makes a problem a "grid 0/1 BFS"?

  • You're on a 2D grid, moving in 4 (or 8) directions
  • Some cells/moves are "free" (cost 0) and some have a cost of 1
  • You want the minimum cost path from one cell to another
  • Common framings: minimum obstacles to remove, minimum walls to break, minimum HP lost

Pattern #2 — Virtual Nodes Trick

Patterns · ~30 min

🎒 Real Example: Teleportation System

You're in a city. Moving between adjacent intersections costs 1. But there are special teleporters: from certain spots, you can teleport to ANY other teleporter for free (cost 0). How do you model this efficiently?

If you have 100 teleporters, connecting every pair would be 100×100 = 10,000 edges. Too slow!

💡 The Virtual Node Trick

Instead of connecting every teleporter to every other, create ONE virtual node that represents the "teleporter network." Then:

  • Each teleporter → virtual node: edge weight = 0 (entering the network is free)
  • Virtual node → each teleporter: edge weight = 0 (exiting is also free)

Now instead of O(T²) edges for T teleporters, you only have O(T) edges! And the total cost of using any teleporter is still 0.

JAVA Virtual Node — Teleporter Example 
import java.util.*;

public class VirtualNodeBFS {

    static class Edge {
        int to, w;
        Edge(int to, int w) { this.to = to; this.w = w; }
    }

    public static int minCost(int n, int[][] roads, int[] teleporters,
                                int src, int dst) {
        // Nodes 0..n-1 are real nodes
        // Node 'n' is the VIRTUAL teleporter hub node
        int virtualNode = n;
        int total = n + 1;

        List<List<Edge>> graph = new ArrayList<>();
        for (int i = 0; i < total; i++) graph.add(new ArrayList<>());

        // Regular roads cost 1
        for (int[] road : roads) {
            graph.get(road[0]).add(new Edge(road[1], 1));
            graph.get(road[1]).add(new Edge(road[0], 1));
        }

        // Connect each teleporter ↔ virtual node (cost 0)
        for (int t : teleporters) {
            graph.get(t).add(new Edge(virtualNode, 0));  // Enter hub
            graph.get(virtualNode).add(new Edge(t, 0));       // Exit hub
        }

        // Standard 0/1 BFS from here
        int[] dist = new int[total];
        Arrays.fill(dist, Integer.MAX_VALUE);
        dist[src] = 0;

        Deque<Integer> dq = new ArrayDeque<>();
        dq.addFirst(src);

        while (!dq.isEmpty()) {
            int u = dq.pollFirst();
            for (Edge e : graph.get(u)) {
                int nd = dist[u] + e.w;
                if (nd < dist[e.to]) {
                    dist[e.to] = nd;
                    if (e.w == 0) dq.addFirst(e.to);
                    else            dq.addLast(e.to);
                }
            }
        }

        return dist[dst] == Integer.MAX_VALUE ? -1 : dist[dst];
    }
}
💡

Virtual nodes are a powerful general technique. You add "fake" nodes to the graph that don't exist in the original problem, but make the graph much easier to represent. This is used in advanced problems with groups, layers, or shared resources.

Pattern #3 — State Graphs (Multi-dimensional BFS)

Patterns · ~35 min

🔐 Real Example: Laser Gate with One Shield

You're navigating a grid. Some cells have laser gates — you can pass through them, but it costs 1 activation. BUT you have one shield. If you use the shield, one laser gate is free. You want to reach the exit with minimum activations.

Key insight: your state isn't just your position (row, col). It also includes whether you've used the shield or not. So state = (row, col, shieldUsed).

JAVA State Graph — Grid with One Free Pass 
import java.util.*;

public class StateGraphBFS {

    static int[] dx = {0, 0, 1, -1};
    static int[] dy = {1, -1, 0, 0};

    public static int minActivations(int[][] grid) {
        int rows = grid.length, cols = grid[0].length;

        // dist[r][c][shield] = min cost to reach (r,c)
        //   with shield=0 (unused) or shield=1 (used)
        int[][][] dist = new int[rows][cols][2];
        for (int[][] layer : dist)
            for (int[] row : layer) Arrays.fill(row, Integer.MAX_VALUE);
        dist[0][0][0] = 0;  // Start at (0,0), shield not used

        // Deque stores: {row, col, shieldUsed}
        Deque<int[]> dq = new ArrayDeque<>();
        dq.addFirst(new int[]{0, 0, 0});

        while (!dq.isEmpty()) {
            int[] cur = dq.pollFirst();
            int r = cur[0], c = cur[1], shield = cur[2];

            for (int d = 0; d < 4; d++) {
                int nr = r + dx[d], nc = c + dy[d];
                if (nr < 0 || nr >= rows || nc < 0 || nc >= cols) continue;

                boolean isGate = (grid[nr][nc] == 1);  // 1 = laser gate

                // Option A: Enter without shield (always possible)
                int cost = isGate ? 1 : 0;
                int nd = dist[r][c][shield] + cost;
                if (nd < dist[nr][nc][shield]) {
                    dist[nr][nc][shield] = nd;
                    if (cost == 0) dq.addFirst(new int[]{nr, nc, shield});
                    else           dq.addLast(new int[]{nr, nc, shield});
                }

                // Option B: Use shield at a gate (only if shield not used yet)
                if (isGate && shield == 0) {
                    // Shield makes this gate free! Cost = 0.
                    int nd2 = dist[r][c][0];  // no extra cost
                    if (nd2 < dist[nr][nc][1]) {  // shield=1 means it's used now
                        dist[nr][nc][1] = nd2;
                        dq.addFirst(new int[]{nr, nc, 1});  // free, front!
                    }
                }
            }
        }

        int r = rows - 1, c = cols - 1;
        return Math.min(dist[r][c][0], dist[r][c][1]);
    }
}
💡

The State Graph pattern: When you have some "resource" that changes your options (shield, key, fuel, turns remaining), make it part of your state. State = (position + resource status). This creates a new, larger graph — but it's still 0/1 BFS underneath.

Pattern #4 — Path Reconstruction

Patterns · ~20 min

🔁 Getting the actual path, not just the distance

So far we've been finding the shortest distance. But often you also need to know the actual path (which nodes to visit). The trick is simple: maintain a prev[] array that records, for each node, where we came from to get the best distance.

JAVA 0/1 BFS with Path Reconstruction 
import java.util.*;

public class PathReconstruction {

    static class Edge {
        int to, w;
        Edge(int to, int w) { this.to = to; this.w = w; }
    }

    static List<Integer> shortestPath(List<List<Edge>> graph,
                                         int src, int dst, int n) {
        int[] dist = new int[n];
        int[] prev = new int[n];  // prev[i] = where we came from to reach i
        Arrays.fill(dist, Integer.MAX_VALUE);
        Arrays.fill(prev, -1);
        dist[src] = 0;

        Deque<Integer> dq = new ArrayDeque<>();
        dq.addFirst(src);

        while (!dq.isEmpty()) {
            int u = dq.pollFirst();
            for (Edge e : graph.get(u)) {
                int nd = dist[u] + e.w;
                if (nd < dist[e.to]) {
                    dist[e.to] = nd;
                    prev[e.to] = u;  // Record: we came to e.to from u
                    if (e.w == 0) dq.addFirst(e.to);
                    else           dq.addLast(e.to);
                }
            }
        }

        // Reconstruct path by tracing back from dst to src
        List<Integer> path = new ArrayList<>();
        if (dist[dst] == Integer.MAX_VALUE) return path;  // No path

        for (int v = dst; v != -1; v = prev[v]) {
            path.add(v);
        }
        Collections.reverse(path);
        return path;
    }
}

Advanced Examples — Putting It All Together

Advanced · ~45 min

🏙️ Example A: Minimum Cost to Reach Office (LeetCode-style)

Problem: You're on a grid. You can move in 4 directions. Moving to an adjacent cell costs 0 if you move in the cell's "sign direction" (each cell has an arrow pointing one direction), and 1 if you change direction. Find minimum cost to reach bottom-right corner.

This is exactly LeetCode 1368 — Minimum Cost to Make at Least One Valid Path in a Grid!

JAVA LC 1368 — Minimum Cost to Make Valid Path in Grid 
import java.util.*;

class Solution {
    // Directions: 1=right, 2=left, 3=down, 4=up
    int[] dr = {0, 0, 1, -1};
    int[] dc = {1, -1, 0, 0};

    public int minCost(int[][] grid) {
        int R = grid.length, C = grid[0].length;
        int[][] dist = new int[R][C];
        for (int[] row : dist) Arrays.fill(row, Integer.MAX_VALUE);
        dist[0][0] = 0;

        Deque<int[]> dq = new ArrayDeque<>();
        dq.addFirst(new int[]{0, 0});

        while (!dq.isEmpty()) {
            int[] cur = dq.pollFirst();
            int r = cur[0], c = cur[1];

            for (int d = 0; d < 4; d++) {
                int nr = r + dr[d], nc = c + dc[d];
                if (nr < 0 || nr >= R || nc < 0 || nc >= C) continue;

                // If moving in the arrow's direction: cost 0
                // Otherwise: cost 1 (need to change the sign)
                int w = (grid[r][c] - 1 == d) ? 0 : 1;
                int nd = dist[r][c] + w;

                if (nd < dist[nr][nc]) {
                    dist[nr][nc] = nd;
                    if (w == 0) dq.addFirst(new int[]{nr, nc});
                    else          dq.addLast(new int[]{nr, nc});
                }
            }
        }

        return dist[R - 1][C - 1];
    }
}

💰 Example B: Minimum Robberies to Escape (Codeforces style)

Problem: You're a thief escaping a city. You can move between districts. Moving through some checkpoints requires bribing a guard (costs 1). Others are unguarded (cost 0). Find minimum bribes needed to escape.

This is just standard graph 0/1 BFS! Model each district as a node, unguarded crossings as 0-weight edges, guarded ones as 1-weight edges. Run 0/1 BFS from your starting district to the escape node.

🔄 Example C: Minimum Changes to Make String Palindrome-adjacent

Problem: You have a string of characters on a graph path. Moving forward along the path costs 0 if the characters already match (palindrome condition). It costs 1 if you need to change one character. Find minimum changes.

Here, each "node" is an index in the string, and the 0/1 edge weight is determined by character comparison. 0/1 BFS finds the minimum total changes needed.

🧠

Advanced recognition skill: The hardest part of 0/1 BFS problems is recognizing them. Key signals — (1) you want a "minimum something," (2) the thing you're minimizing only goes up by 0 or 1 at each step, (3) you're traversing a graph or grid. When you see these three together, think 0/1 BFS immediately.

Common Mistakes — Don't Fall Into These

Advanced · ~20 min

❌ Mistake 1: Using a visited[] array like normal BFS

In normal BFS (unweighted), once you visit a node, you never revisit it. In 0/1 BFS, you can update a node's distance multiple times! Using visited[] will skip these updates and give wrong answers.

Fix: Instead of checking visited[], check if (newDist < dist[neighbor]). Only update when you find a shorter path.

❌ Mistake 2: Pushing to wrong end of deque

Remember: 0-cost edges → addFirst(). 1-cost edges → addLast(). Getting these backwards gives completely wrong distances. Double-check your edge weights and which end you're pushing to.

❌ Mistake 3: Not initializing dist[] to MAX_VALUE

If you initialize to 0 or -1, the condition if (newDist < dist[neighbor]) might not work correctly. Always fill with Integer.MAX_VALUE and set dist[source] = 0.

❌ Mistake 4: Using 0/1 BFS when weights aren't 0 or 1

0/1 BFS ONLY works when all edge weights are exactly 0 or 1. If you have weights like 2, 3, or 5, use Dijkstra or Bellman-Ford. Using 0/1 BFS with other weights gives wrong answers silently — dangerous!

❌ Mistake 5: Forgetting to update dist before pushing to deque

Always update dist[neighbor] = newDist BEFORE pushing neighbor to the deque. If you push first and update later, other threads of BFS might process neighbor with the old (wrong) distance.

⚠️

Pro tip for debugging: If your 0/1 BFS gives wrong answers, first check: are all your edge weights really 0 or 1? Are you using addFirst/addLast correctly? Are you missing visited[] and using dist comparison instead?

📋 Summary — What you've learned

  • What 0/1 BFS is: Finding shortest paths in graphs where every edge costs 0 or 1
  • Why it works: The deque trick keeps nodes sorted by cost without a priority queue
  • Core rule: 0-cost → addFirst(), 1-cost → addLast(), always pollFirst()
  • Patterns: Grid problems, virtual nodes, state graphs, path reconstruction
  • Complexity: O(V + E) — same as normal BFS, much better than Dijkstra for 0/1 graphs
  • Common mistakes: visited[] array, wrong deque end, weights not actually 0/1
