State-Space Graph Algorithms for Advanced Competitive Programming

🧠 The Core Concept: What is a State-Space Graph?

Standard Dijkstra or BFS algorithms fail when a problem introduces a conditional constraint—like having a discount coupon, a limited number of layovers, or the ability to break through walls. A greedy algorithm might overwrite a path that is currently more expensive, failing to realize that path preserves a resource needed later.

The Solution: We create a "Multiverse" by adding an extra dimension to our distance/visited array. Instead of dist[node], we use dist[node][state].

Using a resource (like a coupon or a wall-breaker) acts as a portal, shifting our path from Universe 0 into Universe 1. This prevents paths with different resource states from illegally overwriting each other in the Priority Queue.

🎟️ Category 1: The Resource Limits

These problems give you a limited resource (stops, time, coupons) and ask for the optimal path.

  • 1. Minimum Cost to Reach City With Discounts (LeetCode 2093)
    State: dist[current_city][discounts_used]

    The Breakdown: The exact same logic as our Flight Discount problem, but instead of 1 coupon, you have K coupons. You maintain K+1 parallel universes.

    🔗 Solve on LeetCode (Premium)
  • 2. Cheapest Flights Within K Stops (LeetCode 787)
    State: dist[current_city][stops_taken]

    The Breakdown: A classic. A cheaper flight path is invalid if it takes too many layovers. The state tracks how many flights you've taken to prevent a cheap-but-long route from overwriting an expensive-but-direct route.

    🔗 Solve on LeetCode
  • 3. Minimum Cost to Reach Destination in Time (LeetCode 1928)
    State: dist[current_city][time_spent]

    The Breakdown: Minimize the cost (passing fees), but you have a strict time limit. A slower, more expensive path in one universe might be the only valid option if the fast path runs out of time.

    🔗 Solve on LeetCode
  • 4. Second Minimum Time to Reach Destination (LeetCode 2045)
    State: dist[current_city][0_or_1]

    The Breakdown: Instead of a resource, the state tracks the absolute shortest time [0] and the strict second shortest time [1] simultaneously.

    🔗 Solve on LeetCode

🔨 Category 2: The Grid Smashers

Grid BFS problems where you are allowed to break the rules of the maze a limited number of times.

  • 5. Shortest Path in a Grid with Obstacles Elimination (LeetCode 1293)
    State: visited[row][col][walls_broken]

    The Breakdown: A Google interview favorite. You can walk through walls, but only K times. Jumping into a wall teleports you to a lower universe where your sledgehammer durability is reduced.

    🔗 Solve on LeetCode

🐉 Category 3: The Bitmask Final Bosses

The ultimate evolution. Instead of tracking a single integer counter, the state uses a binary bitmask to track an entire inventory of items or visited nodes.

  • 6. Shortest Path to Get All Keys (LeetCode 864)
    State: visited[row][col][keys_bitmask]

    The Breakdown: You navigate a maze with locked doors. You can only pass a door if you have the key. Picking up a key acts as a portal to a new universe where that specific door is forever unlocked.

    🔗 Solve on LeetCode
  • 7. Shortest Path Visiting All Nodes (LeetCode 847)
    State: visited[current_node][visited_nodes_bitmask]

    The Breakdown: An unweighted graph where you must visit every node, allowing revisits. The state tracks exactly which combination of nodes you have seen so far to prevent infinite loops while allowing necessary backtracking.

    🔗 Solve on LeetCode
