01

The Core Intuition 🧠

Imagine you're getting dressed. You can't wear shoes before socks. You can't wear a shirt before your undershirt. There's a dependency order. Topological sort is just "figure out the right order to do things when some things must come before others."

💡 The Golden Rule
Topo Sort + DP = "When I've finished everything that comes before me, I can compute my own best answer using those results." This is exactly what DP on a DAG is: process nodes in dependency order, and each node inherits/extends the answers from its parents.

Dynamic programming needs the property: when you compute dp[node], all nodes that feed into it are already computed. Topological order guarantees exactly that — you see every prerequisite before you see the node itself.

# Example: Course prerequisites
Course A ──▶ Course B ──▶ Course D
Course A ──▶ Course C ──▶ Course D

# Topo order: A → B → C → D (one valid order)
# DP: dp[D] = dp[B] + dp[C] + 1 (longest path through D)

02

Topological Sort — Two Ways 🔄

There are exactly two algorithms for topological sort. Both give you a valid ordering. For DP on DAGs, Kahn's BFS is usually easier because it naturally processes nodes "level by level" and you can compute DP values on-the-fly.

Method 1: Kahn's Algorithm (BFS + In-degree)

1
Compute in-degree for every node

In-degree = how many edges point INTO this node. A node with in-degree 0 has no prerequisites — it can go first.

2
Push all in-degree-0 nodes into a queue

These are your starting points. They have nothing depending on them.

3
Process queue: pop a node, update DP, reduce neighbor in-degrees

When a neighbor's in-degree hits 0, push it into the queue. Do your DP computation here!

4
If you processed all nodes — success. If not — there was a cycle.

This is also how you detect cycles in a directed graph.

# Kahn's Algorithm — Clean Python
from collections import deque

def kahn_topo_sort(n, edges):
    # Build graph and in-degree array
    adj = [[] for _ in range(n)]
    in_deg = [0] * n

    for u, v in edges:
        adj[u].append(v)
        in_deg[v] += 1

    # Start with all zero-indegree nodes
    q = deque([i for i in range(n) if in_deg[i] == 0])
    order = []

    while q:
        node = q.popleft()
        order.append(node)
        for nei in adj[node]:
            in_deg[nei] -= 1
            if in_deg[nei] == 0:
                q.append(nei)

    # len(order) != n means cycle exists
    return order if len(order) == n else []
Python

Method 2: DFS-based (Recursive / Iterative)

Run DFS on every unvisited node. After you've explored all children of a node, push it to a stack. Reverse the stack → topo order. Great for memoized DFS (where you compute dp[node] after recursing into neighbors). 

# DFS Topo Sort — Python
def dfs_topo_sort(n, adj):
    visited = [False] * n
    stack = []

    def dfs(u):
        visited[u] = True
        for v in adj[u]:
            if not visited[v]:
                dfs(v)
        stack.append(u)   # push AFTER children are done

    for i in range(n):
        if not visited[i]:
            dfs(i)

    return stack[::-1]   # reverse = topo order
Python
⚠️ Important Distinction
Kahn's BFS = naturally process nodes level-by-level → easy to attach DP updates inline.
DFS = attach DP at the "return" step of recursion → natural for memoization / top-down DP.
Both work! Choose based on what feels cleaner for the specific problem.
03

Why Does DP Fit Perfectly? 🎯

DP requires optimal substructure: the best answer for a node depends only on the best answers for its sub-problems. In a DAG, "sub-problems" = previous nodes in topological order. There are no back-edges (cycles), so you never run into circular dependencies.

The Universal DP Recurrence on DAGs

dp[node] = f( dp[predecessor₁], dp[predecessor₂], ... )

Where f is whatever your problem needs: max, min, sum, product, count, etc. Because you process nodes in topo order, every predecessor is already computed. This is literally the definition of why topological sort and DP are best friends.

The 7 Core Patterns 🏗️

Pattern 1

🔥 Longest Path in a DAG

The most classic pattern. dp[v] = longest path ending at v. Extend from every predecessor.

Classic example: Longest Increasing Subsequence (LIS) can be modeled as a DAG where you draw an edge from i→j if arr[i] < arr[j] and i < j. Then LIS = longest path in this DAG. 

# Longest Path in a DAG using Kahn's + DP
def longest_path(n, edges, weights):
    adj = [[] for _ in range(n)]
    in_deg = [0] * n

    for u, v in edges:
        adj[u].append(v)
        in_deg[v] += 1

    dp = [weights[i] for i in range(n)]   # start with own weight
    q = deque([i for i in range(n) if in_deg[i] == 0])

    while q:
        u = q.popleft()
        for v in adj[u]:
            # KEY STEP: extend best path through u to v
            dp[v] = max(dp[v], dp[u] + weights[v])
            in_deg[v] -= 1
            if in_deg[v] == 0:
                q.append(v)

    return max(dp)
Python
Pattern 2

📊 Count Paths in a DAG

dp[v] = number of distinct paths from source to v. dp[v] = sum of dp[all predecessors of v].

Used in: probability over DAGs, counting distinct arrangements respecting constraints, number of ways to finish tasks in valid orders. 

# Count all paths from source (node 0) to each node
def count_paths(n, edges):
    adj = [[] for _ in range(n)]
    in_deg = [0] * n

    for u, v in edges:
        adj[u].append(v)
        in_deg[v] += 1

    dp = [0] * n
    dp[0] = 1   # 1 way to be at source
    q = deque([i for i in range(n) if in_deg[i] == 0])

    while q:
        u = q.popleft()
        for v in adj[u]:
            dp[v] += dp[u]   # add all paths coming through u
            in_deg[v] -= 1
            if in_deg[v] == 0:
                q.append(v)

    return dp   # dp[i] = # paths from 0 to i
Python
Pattern 3

🗓️ Task Scheduling / Earliest Completion Time

Each task has a duration. Task B can only start after A finishes. What's the earliest each task can complete? dp[v] = max(dp[u] + dur[u]) over all u→v. This is literally CPM (Critical Path Method). 

# Earliest start time for each task (CPM)
def earliest_completion(n, edges, duration):
    adj = [[] for _ in range(n)]
    in_deg = [0] * n

    for u, v in edges:
        adj[u].append(v)
        in_deg[v] += 1

    # dp[v] = earliest time to START task v
    dp = [0] * n
    q = deque([i for i in range(n) if in_deg[i] == 0])

    while q:
        u = q.popleft()
        for v in adj[u]:
            # v can't start until u is done (dp[u] + duration[u])
            dp[v] = max(dp[v], dp[u] + duration[u])
            in_deg[v] -= 1
            if in_deg[v] == 0:
                q.append(v)

    # Total time = max over all tasks of (start + duration)
    return max(dp[i] + duration[i] for i in range(n))
Python
Pattern 4

🧩 DP on Implicit DAG (LIS, LCS variants)

Sometimes the graph is not given explicitly — you construct it from the problem's ordering rules. LIS, Longest Bitonic Subsequence, Longest Chain of Pairs are all "build DAG from rules → longest path."

The trick: define the DAG implicitly. "There's an edge from i to j if condition(i, j) is true." Then longest path in this implicit DAG = your answer. 

# LIS via explicit DAG DP — O(n²)
def lis(arr):
    n = len(arr)
    # dp[i] = length of LIS ending at index i
    dp = [1] * n

    for j in range(1, n):
        for i in range(j):
            if arr[i] < arr[j]:     # edge i → j exists
                dp[j] = max(dp[j], dp[i] + 1)

    return max(dp)   # this IS topo DP on the implicit DAG!
Python
💡 Key Insight
The for j in range(n) outer loop is your topological ordering! Since j always increases, and edges only go from smaller index to larger, you're processing in topo order automatically.
Pattern 5

🔄 Memoized DFS on DAG (Top-Down)

Instead of BFS + explicit topo order, recurse into the graph and cache results. Python's @cache or a memo dict handles this. Works great when the DAG is implicit or complex. 

# Memoized DFS — longest path from each node
from functools import lru_cache

def longest_path_memo(n, adj):
    @lru_cache(maxsize=None)
    def dp(u):
        best = 0
        for v in adj[u]:
            best = max(best, dp(v) + 1)
        return best

    return max(dp(i) for i in range(n))

# The magic: lru_cache ensures each node is computed ONCE.
# Recursion implicitly respects topo order (children computed before parents return).
Python
Pattern 6

🌊 Lexicographically Smallest Topo Order

Use a min-heap instead of a regular queue in Kahn's algorithm. At each step, pick the smallest-index node with in-degree 0. 

import heapq

def lex_smallest_topo(n, edges):
    adj = [[] for _ in range(n)]
    in_deg = [0] * n

    for u, v in edges:
        adj[u].append(v)
        in_deg[v] += 1

    heap = [i for i in range(n) if in_deg[i] == 0]
    heapq.heapify(heap)
    order = []

    while heap:
        u = heapq.heappop(heap)   # always pick smallest!
        order.append(u)
        for v in adj[u]:
            in_deg[v] -= 1
            if in_deg[v] == 0:
                heapq.heappush(heap, v)

    return order
Python
Pattern 7

💎 DP on DAG with State (Multi-Dimensional DP)

Sometimes dp[node] is not a single number but a tuple or dictionary. Example: dp[node] = (max_score, min_steps) — you want max score with fewest steps as tiebreaker. Or dp[node][mask] for bitmask DP on DAG. 

# Bitmask DP on DAG — all subsets must be completed
# Example: jobs with prerequisites, want min cost to do all
def bitmask_dag_dp(n, prerequisites, cost):
    # dp[mask] = min cost to complete exactly the jobs in 'mask'
    dp = [float('inf')] * (1 << n)
    dp[0] = 0

    for mask in range(1 << n):
        if dp[mask] == float('inf'): continue
        for job in range(n):
            if mask & (1 << job): continue  # already done
            # Check all prerequisites are in mask
            prereq_mask = prerequisites[job]
            if (mask & prereq_mask) == prereq_mask:
                new_mask = mask | (1 << job)
                dp[new_mask] = min(dp[new_mask], dp[mask] + cost[job])

    return dp[(1 << n) - 1]  # all jobs done
Python

The Reusable Template 📋

Here's your copy-paste, fill-in-the-blank template for 90% of Topo Sort + DP problems. The only things you change are: the DP recurrence and the DP initialization. 

################################
# TOPO SORT + DP  —  Master Template
################################
from collections import deque

def topo_dp(n, edges,
             init_dp,         # function(node) -> initial dp value
             update_dp,       # function(dp, u, v) -> updates dp[v] using dp[u]
             edge_weight=None # optional: {(u,v): weight}
             ):
    # ── 1. Build graph ──────────────────────────────
    adj = [[] for _ in range(n)]
    in_deg = [0] * n

    for u, v in edges:
        adj[u].append(v)
        in_deg[v] += 1

    # ── 2. Initialize DP ────────────────────────────
    dp = [init_dp(i) for i in range(n)]

    # ── 3. Kahn's BFS ───────────────────────────────
    q = deque([i for i in range(n) if in_deg[i] == 0])
    processed = 0

    while q:
        u = q.popleft()
        processed += 1

        for v in adj[u]:
            # ── 4. YOUR DP RECURRENCE HERE ──────────────
            update_dp(dp, u, v)   # e.g. dp[v] = max(dp[v], dp[u] + 1)

            in_deg[v] -= 1
            if in_deg[v] == 0:
                q.append(v)

    # ── 5. Check for cycle ──────────────────────────
    if processed != n:
        return None   # cycle detected!

    return dp

###############################################
# Concrete usage examples:
###############################################

# 1. Longest path
dp = topo_dp(n, edges,
             init_dp=lambda i: node_value[i],
             update_dp=lambda dp, u, v: dp.__setitem__(v, max(dp[v], dp[u] + node_value[v])))

# 2. Count paths from source

             init_dp=lambda i: 1 if i == source else 0,

# 3. Shortest path (min cost)

             init_dp=lambda i: 0 if i == source else float('inf'),
             update_dp=lambda dp, u, v: dp.__setitem__(v, min(dp[v], dp[u] + cost[(u,v)])))

# LC 329 — Longest Increasing Path in Matrix
def longestIncreasingPath(matrix):
    if not matrix: return 0
    m, n = len(matrix), len(matrix[0])
    dirs = [(0,1),(0,-1),(1,0),(-1,0)]

    from functools import lru_cache

    @lru_cache(maxsize=None)
    def dp(r, c):
        best = 1
        for dr, dc in dirs:
            nr, nc = r+dr, c+dc
            if 0 <= nr < m and 0 <= nc < n and matrix[nr][nc] > matrix[r][c]:
                best = max(best, dp(nr, nc) + 1)  # DAG edge: smaller → larger
        return best

    return max(dp(r,c) for r in range(m) for c in range(n))

# LC 2050 — Parallel Courses III
def minimumTime(n, relations, time):
    adj = [[] for _ in range(n+1)]
    in_deg = [0] * (n+1)

    for u, v in relations:
        adj[u].append(v)
        in_deg[v] += 1

    # dp[i] = earliest time course i CAN FINISH
    dp = [0] * (n+1)

    q = deque(i for i in range(1, n+1) if in_deg[i] == 0)
    for node in q: dp[node] = time[node-1]  # no prereqs

    while q:
        u = q.popleft()
        for v in adj[u]:
            # v can start only after u finishes
            dp[v] = max(dp[v], dp[u] + time[v-1])
            in_deg[v] -= 1
            if in_deg[v] == 0:
                q.append(v)

    return max(dp[1:n+1])

# LC 1857 — Largest Color Value in Directed Graph
def largestPathValue(colors, edges):
    n = len(colors)
    adj = [[] for _ in range(n)]
    in_deg = [0] * n

    for u, v in edges:
        adj[u].append(v)
        in_deg[v] += 1

    # dp[node][c] = max occurrences of color c on any path ending at node
    dp = [[0] * 26 for _ in range(n)]

    q = deque(i for i in range(n) if in_deg[i] == 0)
    for node in q:
        dp[node][ord(colors[node]) - ord('a')] = 1

    processed = 0
    ans = 1

    while q:
        u = q.popleft()
        processed += 1
        ans = max(ans, max(dp[u]))

        for v in adj[u]:
            c = ord(colors[v]) - ord('a')
            for color in range(26):
                dp[v][color] = max(dp[v][color], dp[u][color] + (color == c))
            in_deg[v] -= 1
            if in_deg[v] == 0:
                q.append(v)

    return -1 if processed != n else ans

The Alien Dictionary Problem — Fully Solved

This is the #1 most asked topo sort interview problem. Here's the complete solution:

# Alien Dictionary — Full Solution
def alienOrder(words):
    # Step 1: Collect all unique chars
    adj = {c: set() for word in words for c in word}

    # Step 2: Compare adjacent words to find ordering
    for i in range(len(words) - 1):
        w1, w2 = words[i], words[i+1]
        min_len = min(len(w1), len(w2))

        # Edge case: "abc" before "ab" is IMPOSSIBLE
        if len(w1) > len(w2) and w1[:min_len] == w2[:min_len]:
            return ""

        for j in range(min_len):
            if w1[j] != w2[j]:
                adj[w1[j]].add(w2[j])   # w1[j] must come before w2[j]
                break

    # Step 3: Topo sort via DFS with cycle detection
    # visited: 0=unvisited, 1=in stack (cycle!), 2=done
    visited = {}
    result = []

    def dfs(c):
        if c in visited:
            return visited[c] == 2  # True if already done, False if cycle
        visited[c] = 1             # mark as in-progress
        for nei in adj[c]:
            if not dfs(nei): return False  # cycle!
        visited[c] = 2             # mark as done
        result.append(c)
        return True

    for c in adj:
        if not dfs(c): return ""

    return "".join(reversed(result))  # reverse DFS topo

# Time: O(C) where C = total chars across all words
# Space: O(1) since at most 26 chars

Common Pitfalls & How to Avoid Them 🐛

❌ Pitfall 1: Forgetting to Check for Cycles
The bug: Running topo sort on a graph that might have cycles without checking.
The fix: Always check if processed_count == n in Kahn's. If not, there's a cycle → return -1, [], or "Impossible".
❌ Pitfall 2: Wrong DP Initialization
The bug: Setting dp[v] = 0 when it should be dp[v] = -infinity (for max) or dp[v] = infinity (for min).
The fix: For longest path, init dp[source] = weight[source], and all others start at their own weight (not 0). For shortest path, init non-source as float('inf').
❌ Pitfall 3: Not Including the Node's Own Value
The bug: dp[v] = max(dp[u]) instead of max(dp[u] + value[v]).
The fix: Remember dp[v] usually means "best path ending AT v", so v's own value must be included.
❌ Pitfall 4: Direction Confusion
The bug: Building edges in the wrong direction. Edge should go from prerequisite → dependent, not the other way.
The fix: Always verify: "If A must be done before B, the edge is A → B."
❌ Pitfall 5: Not Handling Disconnected Graphs
The bug: Only starting DFS/BFS from node 0, missing disconnected components.
The fix: In Kahn's, push ALL in-degree-0 nodes initially. In DFS, loop over all nodes and start dfs if unvisited.
❌ Pitfall 6: Updating DP Before or After Decrementing In-degree
The bug: Incorrect order of updating DP vs decrementing in-degree.
The fix: The correct order is: (1) update dp[v] using dp[u], then (2) decrement in_deg[v], then (3) if in_deg[v]==0, push to queue.

The Mental Model — Remember This 🧲

The 5-Second Mental Check

"Are there dependencies? Then there's a DAG. Is there an optimization? Then there's DP. DAG + DP = Topo Sort + DP."

Every time you see "A before B" with "maximize/minimize/count something," your brain should immediately jump to: build the DAG, run topo sort, propagate DP values forward. Two changes to the template: initialization and recurrence. That's it.

🔨

Build the DAG

Model every "A before B" constraint as a directed edge A → B. Nodes are your items/tasks/courses.

📐

Define dp[node]

What does the best answer look like when you're AT this node? Length? Cost? Count? Score?

🔁

Write the Recurrence

dp[v] = max/min/sum over all u→v of (dp[u] + something). This is the only line that changes per problem.

✅

Extract the Answer

max(dp), dp[target], sum(dp), or check for cycles (len != n → return -1).
