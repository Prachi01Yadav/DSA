Stamping the Sequence: Think backwards to win forwards 📮⏪

This problem looks like a nasty search over a huge number of stamp orders. It is actually solved by one idea: don't build the target, un-build it. By the end of this page you'll know the trick, why it is correct, the whole family of problems that use the same trick, how to spot it in the wild, and exactly how to apply it.

What you'll get: a story to remember the idea · an interactive visualizer where you type your own stamp and target · proof intuition · complexity · the optimized queue version · bug museum · the pattern family tree with real LeetCode problems · a recognition checklist · an application recipe · a quiz.

1The problem, in plain words

Forget the formal statement for a moment.

You own a rubber stamp that prints a small word, say abc. You also own a long blank strip of paper made of ? cells (blank = "nothing printed yet"). You may press the stamp anywhere on the strip as long as the whole stamp fits on the strip. Each press overwrites whatever was underneath those cells.

You want the strip to finally read exactly target. Output the left-edge index of every press, in order. Use at most 10 × target.length presses. If it's impossible, output an empty list.

Example 2 from the problem (stamp = abca, target = aabcaca) — one valid answer is [0, 3, 1]

Each row is one press, oldest at the top. Faded + crossed-out letters were painted over by a later press. Only the blue letters survive and spell the target. Notice something? The newest stamp is always 100% visible. Hold that thought. It's the whole problem.

🎯
Key vocabulary

Window = a position i where the stamp could be placed (0 ≤ i ≤ n − m), covering cells i … i+m−1. There are n − m + 1 windows.

n = target length, m = stamp length.

2Why going forward is a trap 🪤

Understanding why the obvious approach fails is half of learning the real one.

The forward instinct: "put the stamp where target starts matching, then continue…". Let's feel the pain:

  • Too many choices. At each of up to 10n steps you choose among n−m+1 positions. That's an astronomically large tree.
  • Early stamps are lies. A stamp you place early may show junk letters that only get fixed by later overwrites. You can't tell, looking at the current string, whether a wrong-looking letter is "a mistake" or "fine, will be overwritten later".
  • Overlaps create dependencies. Press A must come before press B only because B overwrites part of A. Forward, you don't know those dependencies yet.
💥
The forward-greedy attempt that breaks

stamp = abca, target = aabcaca. A forward-greedy "stamp where the first letters match" might put abca at 0 and get abca???, but position 1 needs to be a while the stamp put b there. Fixing it requires a later stamp that overwrites index 1, which itself must start at index 1 (or earlier) and clobber more cells… you are now guessing a chain of future overwrites. Forward thinking has no good "local rule".

Forward is hard because the future is uncertain. So let's make the future the past.

3THE BIG IDEA: rewind the movie ⏪

Think of the film Memento: the story makes sense only when told backwards.

💡
Aha #1 — The last stamp is fully visible.

Whatever stamp you pressed last has nothing painted over it. So in the final string, there must be a window that reads exactly like the stamp. That window is easy to find: just compare each window of target with stamp.

💡
Aha #2 — Once the last stamp is found, "erase" it.

Before that last press, those cells held something else (older stamps, or blank). We don't care what — whatever it was got overwritten. So after "undoing" the last press, those cells become don't-care cells. We mark them ?.

💡
Aha #3 — Repeat: now the second-to-last stamp is fully visible, except for don't-care cells.

The second-to-last press was only covered by the last press. Those covered cells are now ?. So we look for a window where every cell is either ? or already equals the stamp's letter. Un-press it. More ?. Repeat until the entire string is ?. The sequence we found, read backwards, is the answer.

The sticker analogy 🧼

Imagine the strip is covered in layers of stickers pasted on top of each other. To strip them off, you can only remove a sticker that's on top — fully visible. After you peel it, the stickers beneath it are exposed. You peel those next. The order you peeled is the exact reverse of the order they were pasted. That is literally what we do. Peel order reversed = paste order.

The detective analogy 🕵️

At a crime scene, the most recent event leaves the clearest evidence (fresh footprints). Older events are partially overwritten. A good detective reconstructs the timeline from newest to oldest: explain the freshest evidence, mentally remove it, and what remains reveals the previous event.

One-line summary of the whole problem

🧠

Repeatedly find a window that matches the stamp (treating ? as "matches anything"), turn it into all ?, record its index. Stop when everything is ?. Reverse the recorded indices.

4The magic ? wildcard ✨

Why one extra symbol turns an impossible search into a simple loop.

The ? in the reverse process has a precise meaning: "this cell will be overwritten by a later press (in forward time), so its current letter is irrelevant."

So when we test a window against the stamp, each cell falls in exactly one of three buckets:

Cell in target windowCompare with stamp letterVerdict
a real letter equal to stamp'smatchok — counts as a real match
?anythingwildcard — free pass
a real letter different from stamp'sconflictbad — window can't be peeled now

A window is peelable when it has no bad cells and at least one real match (otherwise it's all ? already and peeling achieves nothing).

🔑
Wildcards only ever make things easier

Turning cells into ? never turns a peelable window into an unpeelable one — it can only convert "bad" cells into wildcards. That monotonicity (more ? ⇒ more windows peelable) is the reason a simple greedy is correct. We prove it in §8.

7The algorithm + code 💻

The simple "repeat-scan" greedy. Easy to write in an interview, fast enough for n ≤ 1000.

Pseudocode

t = target as mutable chars
stars = 0, order = []
while stars < n:
    progress = false
    for i in 0 .. n-m:                       # every window
        c = tryUnstamp(i)                    # returns #real letters erased, or 0
        if c > 0:
            order.append(i); stars += c; progress = true
    if not progress: return []               # stuck => impossible
return reverse(order)

tryUnstamp(i):
    real = 0
    for j in 0 .. m-1:
        if t[i+j] == '?':          continue          # wildcard
        if t[i+j] != stamp[j]:     return 0          # conflict
        real += 1
    if real == 0: return 0                           # all '?', useless
    set t[i..i+m-1] = '?'
    return real
⚡
Free quick-reject (nice interview bonus)

Cell 0 is covered by exactly one window (index 0), so target[0] must equal stamp[0]. Likewise target[n−1] must equal stamp[m−1]. If either fails, return [] immediately. (The loop would discover it anyway; this just saves time and shows insight.)

8Why greedy is correct 🧪

Greedy algorithms scare people because "why is it OK to just pick any?" Here is the intuition-level proof.

Lemma 1 · Monotone

If a window is peelable now, it stays peelable after any other peeling. Peeling only converts real letters into ?, and ? never causes a conflict. A window that matched before still has no conflicts. ✔️

Lemma 2 · Order doesn't matter (confluence)

Because of Lemma 1, peeling window A can never ruin the chance to peel B. So the final set of ? cells you reach by exhaustively peeling is the same regardless of choices — it's a closure/fixpoint, like repeatedly applying a rule until nothing changes.

Lemma 3 · Greedy finds a solution iff one exists

(⇐) If a valid forward stamping sequence exists: reverse it. The newest stamp is fully visible ⇒ peelable. Remove it, and the second-newest is visible apart from cells already peeled (which are ?) ⇒ peelable, and so on. So some order peels everything. By Lemma 2, greedy reaches the same maximal closure, so it also peels everything.

(⇒) If greedy peels everything: reverse its order. Every cell's final letter comes from the last forward press covering it — which is the window that first turned it into ? in the reverse process; at that moment the cell held its real target letter, and the window had no conflicts, so that letter equals the stamp's letter there. Hence the forward replay produces exactly target. ✔️

🧩
Why we need "at least one real letter"

A window of all ? matches trivially but erases nothing. If we counted it as progress, the loop would never terminate, and we'd output pointless stamps. Progress must mean new ? appeared.

9Complexity & the mysterious 10N bound 📏

VersionTimeSpaceNotes
Repeat-scan greedy (§7)O(N · (N−M+1) · M) worst caseO(N)≤ N passes (each non-final pass erases ≥1 cell); each pass scans N−M+1 windows × M cells. Real inputs are far faster.
Queue / topological (§10)O(N · M)O(N · M)Each cell turns to ? once and touches ≤ M windows.
🔢
The 10·N limit is a red herring (a generous bound)

In our solution each window is peeled at most once (after peeling it's all ? and gets ignored). So we output at most N − M + 1 ≤ N indices — far below 10N. The bound exists to stop you from thinking you need cleverly minimal sequences. You don't: any valid sequence works.

That's also a recognition signal: when a problem gives a very generous operation cap, it's hinting "construct something valid, don't optimize".

10Pro version: the queue (topological peeling) 🚀

The repeat-scan wastes time re-checking windows that haven't changed. Fix it with the same trick as Kahn's topological sort.

For every window k keep:

  • made[k]: positions where the window already matches the stamp letter (these are the real letters it will erase).
  • todo[k]: positions that currently conflict. They must each become ? (erased by some other window) before window k can be peeled.

A window with todo = ∅ is peelable. Put it in a queue. When you peel it, every newly erased position pos is removed from the todo set of every window covering it (k ∈ [pos−m+1, pos]). If some todo becomes empty, that window joins the queue.

🔗
This is exactly Kahn's algorithm in disguise

Windows = nodes. "window k waits for position p to be erased" = dependency edge. todo size = in-degree. Queue holds nodes with in-degree 0. Peeling = removing a node and decrementing neighbours' in-degree. The reverse topological order is the stamping order.

⚠️
Subtle bug to avoid

Only enqueue window k when the removal actually removed something and the set is now empty. If you just do remove(pos); if (isEmpty()) enqueue, a window that was already empty from the start gets enqueued again for every overlapping position — duplicates that could blow past the 10N cap.

11Edge cases & the bug museum 🏛️

Edge cases

  • m = 1: stamp is one letter. Possible iff target is that letter repeated. Greedy handles it (each window is a single cell).
  • m = n: exactly one window. Possible iff stamp == target. Answer [0].
  • stamp == target: answer [0].
  • Target uses a letter not in stamp: no window can ever clear it ⇒ [].
  • Ends mismatch: target[0]≠stamp[0] or target[n−1]≠stamp[m−1] ⇒ [].
  • Self-overlapping stamps (like aba) can produce interesting chains — try them in the playground.

Bug museum 🐛

  • Forgetting to reverse the output.
  • Counting an all-? window as a move (infinite loop / bloated answer).
  • Treating ? as a literal letter instead of a wildcard.
  • Not checking that every cell became ? at the end (queue version).
  • Off-by-one on window range: valid starts are 0 … n−m, not n−1.
  • Using immutable Strings in a hot loop instead of a char[].
  • Going forward and hoping.
  • Confusing with LC 2132 "Stamping the Grid" — totally different (2D prefix sums).

12The pattern, named 🏷️

Let's give the trick a handle you can remember under interview stress.

Reverse-Time Greedy with a "Don't-Care" Marker (a.k.a. Peeling)

Statement: If a process builds the final state through overwriting operations, then the last operation is fully visible in the final state. Find it, undo it by replacing what it wrote with a don't-care marker, and repeat. The undo order, reversed, is the operation order.

Three ingredients:

  1. Overwrite semantics (later operations hide earlier ones).
  2. An undo test: "is this operation visible/consistent with the current state?"
  3. A neutral marker (?) that makes already-explained cells stop causing conflicts.

Why it works: monotonic — explaining more only ever makes more operations explainable, so order among available choices doesn't matter.

Many people also call the broader idea "work backwards" or "reverse engineering the last move". The queue implementation is a topological sort by peeling layers.

13The pattern family tree 🌳

Same DNA, different costumes. Knowing the siblings makes the pattern easy to spot.

1 · Think about the LAST operation closest cousin

Instead of "what do I do first?", ask "what happens last?" — it splits the problem cleanly.
  • LC 312 Burst Balloons: the last balloon burst splits the range into independent halves.
  • LC 1547 Min Cost to Cut a Stick: think of the last cut.
  • LC 664 Strange Printer: the last print of a colour over a range is visible; a classic printing/painting overwrite problem (interval DP).
  • LC 546 Remove Boxes, LC 1000 Merge Stones: last-move interval DP.

Shared DNA: reasoning from the end. Difference: those use DP over intervals; Stamping uses a greedy because wildcards make choices commute.

2 · Run the process in reverse undo

The forward move is many-to-one or ambiguous, but the reverse move is forced or simple.
  • LC 780 Reaching Points: from (tx,ty), the larger coordinate must have come from subtraction; go back.
  • LC 991 Broken Calculator: reverse ×2 / −1 into ÷2 / +1.
  • LC 2139 Min Moves to Reach Target Score: halve when possible, going backward from the target.

Shared DNA: start at the answer, undo steps. Difference: they undo a numeric operation; Stamping undoes an overwrite and needs a wildcard.

3 · Peel layers / topological order engine

Repeatedly remove things that have no remaining blockers; each removal unblocks others.
  • LC 207 / 210 Course Schedule I & II (Kahn's algorithm).
  • LC 802 Find Eventual Safe States, LC 310 Min Height Trees (peel leaves).
  • LC 1136 Parallel Courses, LC 269 Alien Dictionary, LC 444 Sequence Reconstruction.

Shared DNA: §10's queue version is this. A window is a node; conflicts are in-edges.

4 · Repeatedly delete matches cascade

Remove pattern occurrences; removals expose new occurrences.
  • LC 1910 Remove All Occurrences of a Substring.
  • LC 1047 / 1209 Remove Adjacent Duplicates (I and II) — stack-based cascades.

Shared DNA: "match, erase, newly exposed match". Difference: they truly delete characters; Stamping keeps a ? placeholder so positions don't shift.

5 · Wildcard matching the ? idea

A symbol that matches anything simplifies conflict checks.
  • LC 44 Wildcard Matching, LC 10 Regular Expression Matching (here wildcards are in the pattern; in Stamping they're in the text).

Useful to remember how to compare "letter vs ?" cleanly.

6 · Fixpoint / closure greedy proof style

Apply any available rule until nothing changes; the end result is unique.
  • LC 802, LC 1857 (topological DP), union-find/BFS "keep expanding" style problems.

If a step can only help future steps, order is irrelevant — your proof tool of choice.

The family at a glance

14How to RECOGNISE it 👀

Tick what's true about a problem you're staring at. The more ticks, the more likely it's a reverse-time/peeling problem.

Tick the boxes…

Trigger phrases in problem statements

  • "place / stamp / paint / overwrite / cover … return the order / sequence of moves"
  • "convert an initial blank state into target using operations" (initial is uniform, target is complex)
  • "at most k · n operations" with a big k
  • "return an empty array if impossible" (feasibility + construction together)

Anti-signals (when it's probably NOT this)

  • Operations commute (additions, XOR, counting) — order is irrelevant, no peeling needed.
  • Operations destroy information irreversibly in ways that can't be tested from the end state.
  • You need the minimum number of operations with a tight bound — often DP (like Strange Printer), where greedy peeling doesn't guarantee minimum.
⚡
The 5-second smell test

Ask: "In the final result, can I point at one operation and say 'this one is completely visible'?" If yes, you can peel it and recurse. That's the pattern.

15How to APPLY it 🛠️

A repeatable recipe. Works on Stamping and on its cousins.

  1. Write the forward process in one sentence. "Start blank; stamp overwrites m consecutive cells."
  2. Find the overwrite relationship. "Later stamps hide earlier ones, so the newest stamp is fully visible."
  3. Define the UNDO. "Erase a visible stamp: its cells become don't-care."
  4. Define the marker and its comparison rule. "? equals anything; a conflict is a real letter ≠ stamp letter."
  5. Define 'undoable now'. "No conflicts, and at least one real letter." Check monotonicity: erasing never makes another undoable op become undoable-no-more.
  6. Pick the engine. Small input → repeat-scan loop. Large input → queue with in-degree counters (Kahn).
  7. Record order, then reverse it. Peel order = reverse of build order.
  8. Check completeness. Are all cells don't-care? If not ⇒ impossible.
  9. Verify by forward replay (do this in tests): stamp in the answer order from blanks and compare to the target.

Reusable template (language-agnostic)

state   = final_state
order   = []
while not all_dont_care(state):
    progress = false
    for op in candidate_operations:
        if visible_and_consistent(op, state) and would_change(op, state):
            mark_dont_care(op, state)      # the UNDO
            order.append(op)
            progress = true
    if not progress: return IMPOSSIBLE
return reversed(order)

Practice applying it to a fresh problem (mini case study)

🖌️ "A wall is painted by repeatedly choosing a contiguous segment and painting it one colour. Given the final wall, output a valid sequence of paint operations (segment + colour)."

Run the recipe: the last paint is a visible solid run of one colour. Peel it (mark don't-care), the next-to-last paint is a solid run ignoring don't-care cells… Same engine, but "operations" are now runs of any length. (Closely related to Strange Printer, where you additionally minimize the count — that's where DP replaces greedy.)

🧱 "Build a string by repeatedly overwriting a window with one of several allowed words. Output an order."

Multiple stamps: for each window try each stamp, same peel rule (no conflicts, at least one real letter). Monotonicity still holds ⇒ same greedy. Only the candidate-operations set grows.

18Cheat sheet 📝

  • Core insight: the last stamp is fully visible ⇒ work backwards.
  • Undo: find a window where every cell is ? or equals the stamp letter, with ≥1 real letter; turn the window into ?.
  • Repeat until everything is ?. If a full pass does nothing ⇒ [].
  • Reverse the recorded indices.
  • Correctness: erasing only helps (monotone) ⇒ order irrelevant ⇒ greedy finds a solution iff one exists.
  • Moves used: ≤ N−M+1 (each window once) ≪ 10N.
  • Complexity: repeat-scan O(N²M) worst; queue O(NM).
  • Quick reject: target[0]==stamp[0] and target[n−1]==stamp[m−1] required.
  • Pattern name: Reverse-time greedy with a wildcard / peeling (topological sort in disguise).
  • Recognise: overwrite ops + output the order + final state given + generous op cap.
