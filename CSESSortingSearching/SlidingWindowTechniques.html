Mastering Sliding Window & Two Pointers

A plain-English, deep-dive guide covering every technique, pattern, and trick used in LeetCode and Codeforces to solve array and string problems.

1. The Core Concept: What is it?

Imagine you are looking at a long strip of photographs, but you are holding a cardboard cutout that only lets you see a few photos at a time. To see the next photo, you slide the cardboard one frame to the right. The photo on the far left disappears from your view, and a new photo on the right appears.

In programming, an array or string is the "strip of photographs". The "cardboard cutout" is your Window. Instead of recalculating everything from scratch every time you move forward, you just subtract the element that left your window, and add the element that entered your window. This turns a slow O(N²) nested-loop solution into a lightning-fast O(N) solution.

2. Fixed-Size Sliding Window Pattern 1

The Scenario: The problem explicitly asks you to look at subarrays/substrings of a fixed length K.

Famous Problems: Max Sum Subarray of size K, First Negative Number in every window of size K, Find All Anagrams in a String.

The Analogy: A train with exactly K cars moving along a track. The length of the train never changes.

The Strategy:

  1. Expand your window by moving the right pointer until it hits size K.
  2. Do your calculation for this window.
  3. To move forward, shift the whole window: add the right element, and remove the left element. Increment both pointers.
# Template for Fixed Window
def fixed_window(arr, k):
    left = 0
    window_sum = 0
    max_sum = 0
    
    for right in range(len(arr)):
        window_sum += arr[right] # Add the new element
        
        # Once we hit window size 'k', we start sliding
        if right - left + 1 == k:
            max_sum = max(max_sum, window_sum) # Process current window
            window_sum -= arr[left]            # Remove the oldest element
            left += 1                          # Slide window forward
            
    return max_sum

3. Variable-Size Sliding Window (Finding Longest) Pattern 2

The Scenario: The window size is NOT fixed. You are asked to find the Longest subarray or substring that satisfies a certain condition.

Famous Problems: Longest Substring Without Repeating Characters, Longest Subarray with Sum ≤ K, Max Consecutive Ones III.

Imagine an elastic rubber band or a caterpillar. The head (right pointer) stretches forward, trying to consume as much as possible to make the longest sequence. But if it eats something bad (condition breaks), the tail (left pointer) shrinks forward until the bad thing is expelled, making the sequence valid again.

The Strategy:

  1. Expand the right pointer to stretch the window.
  2. If the window becomes invalid (e.g., sum > K, or duplicate character found), shrink the window by moving the left pointer until it becomes valid again.
  3. Update your maximum length ONLY when the window is valid.
# Template for Longest Variable Window
def longest_window(arr, target):
    left = 0
    window_sum = 0
    max_length = 0
    
    for right in range(len(arr)):
        window_sum += arr[right] # Expand
        
        # Condition broken? Shrink until valid
        while window_sum > target:
            window_sum -= arr[left]
            left += 1
            
        # Update answer when valid
        max_length = max(max_length, right - left + 1)
        
    return max_length

4. Variable-Size Sliding Window (Finding Shortest) Pattern 3

The Scenario: You need to find the Shortest subarray that satisfies a condition.

Famous Problems: Minimum Size Subarray Sum, Minimum Window Substring.

The Strategy:

This is the exact opposite of the previous pattern. You expand right until the condition is MET. Once met, you try to squeeze the window from the left to see how small you can make it while still satisfying the condition.

# Template for Shortest Variable Window
def shortest_window(arr, target):
    left = 0
    window_sum = 0
    min_length = float('inf')
    
    for right in range(len(arr)):
        window_sum += arr[right]
        
        # Condition MET? Squeeze from left to find the shortest
        while window_sum >= target:
            min_length = min(min_length, right - left + 1)
            window_sum -= arr[left]
            left += 1
            
    return min_length if min_length != float('inf') else 0

5. The "At Most K" Trick (Counting Subarrays) Advanced Pattern

The Scenario: You are asked to count the number of subarrays with EXACTLY K unique elements or K sum.

Famous Problems: Subarrays with K Different Integers, Binary Subarrays With Sum.

The Problem: Sliding windows are terrible at calculating "exactly K" because when you hit "exactly K", you don't know if moving the left pointer or right pointer is the right move to keep it exactly K.

The Mathematical Trick: Instead of calculating "Exactly K", you calculate "At most K" and "At most K-1". Then, subtract them!

Exactly(K) = AtMost(K) - AtMost(K-1)

Counting "At most K" is easy with a standard sliding window: the number of valid subarrays ending at index right is simply right - left + 1.

6. Two Pointers: Opposite Ends Pattern 4

The Scenario: You are usually given a sorted array and need to find a pair of numbers that meet a target, or you need to evaluate symmetry (like palindromes).

Famous Problems: Two Sum II, 3Sum, Container With Most Water, Valid Palindrome, Trapping Rain Water.

The Analogy: Two people standing at opposite ends of a long hallway, walking towards the middle to meet each other based on specific instructions. 
def two_pointers_opposite(arr, target):
    left = 0
    right = len(arr) - 1
    
    while left < right:
        current_sum = arr[left] + arr[right]
        
        if current_sum == target:
            return [left, right]
        elif current_sum < target:
            left += 1  # We need a bigger sum, move left pointer to the right
        else:
            right -= 1 # We need a smaller sum, move right pointer to the left

7. Two Pointers: Fast & Slow (Floyd's Tortoise & Hare) Pattern 5

The Scenario: Often used on Linked Lists or arrays that act like Linked Lists to find cycles or the midpoint.

Famous Problems: Linked List Cycle, Middle of the Linked List, Find the Duplicate Number.

Imagine a Tortoise walking 1 step at a time, and a Hare running 2 steps at a time on a circular track. Eventually, the Hare will lap the Tortoise and they will crash into each other. If there is no cycle, the Hare reaches the end line first.

Summary: How to spot these problems?

  • Keywords: "Subarray", "Substring", "Contiguous sequence", "Consecutive elements", "Pair of elements".
  • Hints: You are asked for max/min length, max/min sum, or count of contiguous elements.
  • Time Complexity constraint: If an O(N²) brute force gives you a Time Limit Exceeded (TLE) error, you almost always need to optimize it to O(N) using one of these patterns.
