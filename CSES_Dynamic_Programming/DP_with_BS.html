The DP + Binary Search Playbook

How to magically drop O(N²) time complexities down to O(N log N)

Pattern 1: Interval Scheduling The Timeline

Use Case: You are given a list of events with a start time, end time, and a reward. You want to pick non-overlapping events to maximize the reward.

💡 The Mental Model: "Looking into the Safe Past"

Imagine building a timeline. If you sort events by when they end, you guarantee that as you move forward, the "past" is set in stone. When evaluating a new event, you use Binary Search to look backwards and find the latest event that finished before your current one started. Because the DP array stores the maximum profit up to that point, grabbing that single past value gives you the best possible combination of prior events.

The Core Implementation (Java)

// 1. Sort strictly by END TIMES
Arrays.sort(events, (a, b) -> Integer.compare(a[1], b[1]));

int[] dp = new int[n];
dp[0] = events[0][2]; // Base case: profit of first event

for (int i = 1; i < n; i++) {
    int skip = dp[i - 1];
    int take = events[i][2];
    
    // 2. Binary Search for the latest valid non-overlapping event
    int s = 0, e = i - 1, ans = -1;
    while (s <= e) {
        int mid = s + (e - s) / 2;
        if (events[mid][1] < events[i][0]) { // If mid ends before i starts
            ans = mid;
            s = mid + 1; // Try to find a later, better event
        } else {
            e = mid - 1;
        }
    }
    
    if (ans != -1) take += dp[ans];
    dp[i] = Math.max(skip, take);
}
When to use: Job Scheduling, CSES Projects, any problem where states overlap in time.

Pattern 2: Monotonic Reduction The Matryoshka

Use Case: You have 2D objects (like envelopes, boxes, or pairs of numbers) and you need to find the longest chain where one fits strictly inside the next.

💡 The Mental Model: "Cheating a Dimension"

A 2D DP table is too slow. Instead, we completely eliminate the Width dimension by sorting widths ascending. But here is the magic trick: if widths are identical, we sort heights descending. Why? Because you can't put a 3x4 envelope into a 3x5 envelope. By forcing the 5 to come before the 4, a standard "Longest Increasing Subsequence" algorithm naturally refuses to pick both! We maintain an active 'tails' array and use Binary Search to slot heights into their optimal place.

The Core Implementation (Java)

// 1. Sort: Width ASCENDING, Height DESCENDING
Arrays.sort(envelopes, (a, b) -> {
    if (a[0] != b[0]) return Integer.compare(a[0], b[0]);
    return Integer.compare(b[1], a[1]); // The Magic Step
});

// 2. LIS Array Tracker
int[] tails = new int[n];
int len = 0;

for (int[] env : envelopes) {
    int height = env[1];
    
    int s = 0, e = len - 1, insertIdx = len;
    
    // Binary search to find where this height belongs in the sequence
    while (s <= e) {
        int mid = s + (e - s) / 2;
        if (tails[mid] >= height) {
            insertIdx = mid; // Replace a larger/equal tail with a smaller one
            e = mid - 1;
        } else {
            s = mid + 1;
        }
    }
    
    tails[insertIdx] = height;
    if (insertIdx == len) len++; // We successfully extended the sequence
}
When to use: Russian Doll Envelopes, Longest Increasing Subsequence, Stacking problems where order doesn't matter initially.
