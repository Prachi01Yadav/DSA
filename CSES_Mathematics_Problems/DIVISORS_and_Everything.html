The Optimal Approach:
GCD and Divisors

Imagine you have a giant array of numbers and you are tasked with finding exactly how many numbers divide all of them perfectly. If you try checking every possible divisor one by one, your program will quickly exhaust its time limit (TLE). But there is a mathematical trick that turns this mountain of a problem into a molehill.

The Core Theorem: Any common divisor of a set of numbers MUST also be a divisor of their Greatest Common Divisor (GCD).

Because of this theorem, we don't need to look at the whole array to find common divisors. We just need to find the overall GCD of the array, and then find the divisors of that single number. Let's break this down into two elegant steps.

1 Shrinking the Array to One Number

Instead of comparing every divisor against every array element, we find the GCD of the entire array. The GCD acts as a "filter" that holds all the prime factors shared by every single element in the array.

Example: Let's say our array is [12, 24, 36].

Instead of checking if 1, 2, 3, 4, 5, 6... divide all three numbers, we calculate their GCD:
• GCD(12, 24) = 12
• GCD(12, 36) = 12
The overall GCD is 12. Now, the problem is incredibly simple: just find the divisors of 12!

2 Counting Divisors in O(√N)

Once we have the overall GCD, how do we count its divisors fast? A naive approach checks every number from 1 to the GCD. But divisors always come in pairs.

For our GCD of 12:

  • If 1 divides 12, then 12 / 1 = 12 (Pair: 1, 12)
  • If 2 divides 12, then 12 / 2 = 6 (Pair: 2, 6)
  • If 3 divides 12, then 12 / 3 = 4 (Pair: 3, 4)

Notice that we only need to check numbers up to the square root of the GCD. For 12, √12 is approx 3.46. By looping only up to 3, we found all divisors by counting both halves of the pair!

Code Implementation (Java)

long g = 0;
// Step 1: Find overall GCD
for (int i = 0; i < n; i++) {
    g = gcd(g, a[i]); 
}

// Step 2: Count divisors up to square root of GCD
long ans = 0;
for (long i = 1; i * i <= g; i++) {
    if (g % i == 0) {
        ans++; // i is a divisor
        
        // Count the paired divisor if it's different
        if (i != g / i) {
            ans++; 
        }
    }
}
System.out.println(ans);

Why is this so fast?

Let's look at the time complexity transformation:

Old Approach

O(M log M)

Checking every multiple of every possible number against a HashSet. For numbers up to 109, this results in Time Limit Exceeded (TLE).

New Approach

O(N + √GCD)

O(N) to find the GCD of the array, plus O(√GCD) to count the divisors. For 109, the loop only runs ~31,622 times. Lightning fast!
