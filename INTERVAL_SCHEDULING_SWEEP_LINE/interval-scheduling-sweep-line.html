Briefing

What is this whole "interval" thing anyway

An interval is just a start and an end. A meeting from 2pm to 3pm. A flight from Delhi to Mumbai. A song that plays from second 30 to second 90. That is it. The moment you have a bunch of "from... to..." things, and a question about how they sit next to each other, you are in interval land.

Almost every interval question is really one of these three questions in disguise:

1. Do things overlap, and how much. 2. If I can only keep some of them, what is the biggest pile I can keep without any overlap. 3. At the busiest moment, how many things are happening at once.

Once you can spot which of these three you are being asked, half the problem is already solved. The other half is picking the right trick, which is what the rest of this page is for.

Sweep Line, explained like you are five

Picture a single vertical line standing at the very start of time. Now walk it slowly to the right, like a scanner moving across a barcode. Every time the line touches the start of an interval, something turns on. Every time it touches the end, that something turns off.

You do not need to check every single point in time, only the moments where something actually changes: a start or an end. Those moments are called events. Sort all the events, walk through them one by one, and keep a running count. That running count tells you how many things are alive at that instant. The highest the count ever climbs is your answer to "how busy does it get".

The whole trick in one line: turn every interval into two events, a +1 when it starts and a -1 when it ends, sort the events by time, and walk through counting.

That is genuinely most of it. Try the little board below, drag the scanner across a real looking work day and watch the count change live.

The Playbook

The eight patterns that cover almost everything

These are not eight unrelated tricks. They are really just two ideas (sort smartly, then either sweep or greedy-pick) wearing different costumes depending on what the question wants.

MERGE

Squash the overlaps together

Sort intervals by start time. Walk through them, and whenever the next one starts before the current one ends, stretch the current one to cover both. If it starts after, close off the current one and begin a new one.

Sort key: start time  |  Used for: merge intervals, calendar cleanup
GREEDY PICK

Fit in the most meetings (Activity Selection)

Sort by end time, not start time. Always grab the interval that finishes earliest and is still free. Finishing early leaves the most room for whatever comes next. This one small idea, sort by end, is the single most reused trick in this whole topic.

Sort key: end time  |  Used for: non overlapping intervals, max meetings, min removals
SWEEP +1/-1

Count how crowded it gets

Turn every interval into a start event and an end event. Sort all events by time. Walk through, add 1 on a start, subtract 1 on an end, and track the highest the counter ever reaches. That peak is your answer.

Sort key: event time  |  Used for: min meeting rooms, max overlap, min platforms
POINT COVER

Burst the balloons with fewest arrows

Sort by end time again. Shoot an arrow right at the end of the first balloon. Any balloon that overlaps that arrow is popped for free. Move to the next unpopped balloon and repeat. Counting arrows fired equals your answer.

Sort key: end time  |  Used for: minimum arrows, minimum points to cover intervals
TWO POINTERS

Walk two sorted lists side by side

When you have two separate sorted lists of intervals and need to find where they overlap, keep one pointer in each list. Compare the two current intervals, record the overlap if any, then move whichever pointer ends first.

Sort key: already sorted, just two pointers  |  Used for: interval list intersections, meeting schedulers
INSERT & SPLICE

Slot a new interval into a clean list

Since the list is already sorted and non overlapping, go in one pass: copy every interval that ends before the new one starts, merge every interval that touches the new one, then copy everything left after.

Sort key: list already sorted  |  Used for: insert interval
DIFF ARRAY

Add a value across a whole range, fast

Instead of looping through every day of a range to add passengers or flowers, just add the value at the start index and subtract it right after the end index. Then take a running sum over the whole array once at the end.

Sort key: index position  |  Used for: car pooling, corporate flight bookings, range updates
SWEEP + HEAP

Track the current tallest, live

The advanced cousin of plain sweeping. As you sweep across start and end events, keep a heap (or ordered structure) of "currently active" values so you can always ask "what is the biggest one right now" in log time.

Sort key: event time  |  Used for: the skyline problem, my calendar III

Terminal 2, The Geometry Wing

Same trick, bigger playground: sweeping over shapes and points

So far our sweep line only walked over a single row of numbers. But the exact same walk-and-count idea also cracks some of the most famous problems in computational geometry. Same rulebook: sort smartly, sweep once, only look at your neighbors. Here are the three big ones.

Finding where lines cross (Line Segment Intersection)

Picture a plate of spaghetti dropped on a table and you want to know every place two noodles touch. Checking every noodle against every other noodle works, but it is slow once you have thousands of them. Here is the shortcut: sweep a vertical line left to right across the table. At any moment, the sweep line is only touching a handful of noodles, and you can line them up top to bottom, like sorting lanes on a highway.

The key idea is sneaky and beautiful: two noodles can only ever cross each other at a moment when they are sitting right next to each other in that top-to-bottom order. So instead of comparing every pair, you only ever compare neighbors. Whenever a crossing shows up, that becomes a new event: the two noodles swap places in the lane order, and you keep sweeping. This shrinks a giant "check everything against everything" job down to a job about neighbors only.

Finding the two closest points (Closest Pair)

Say you have a few thousand dots scattered on a page and you want the two that are nearest to each other. Brute force means comparing every dot to every other dot, painfully slow. The sweep line version does something clever instead: sort all the dots left to right, then walk across them one at a time while keeping track of the closest distance found so far, call it d.

As you walk, you only need to look at dots inside a narrow strip of width d around your current position, since anything farther left or right cannot possibly beat your current best. And inside that thin strip, there is a neat geometric fact: no matter how many dots are in there, you only ever need to check about six or seven of them above and below you. That one little fact is what makes this whole approach fly on huge inputs.

Wrapping a rubber band around everything (Convex Hull)

Now imagine your dots are nails hammered into a board, and you stretch a rubber band around all of them and let go. The shape it snaps into is the convex hull, the smallest loop that still contains every single nail inside it. This one is not a moving vertical line exactly, but it is built the exact same family way: sort first, then sweep through in that sorted order.

Sort every point left to right. Walk through them while building the bottom half of the loop, and every time the last three points you added would make a turn to the right (a dent, basically), pop the middle one out, since a dent can never be part of a tight rubber band. Do that same walk backwards to build the top half, glue the two halves together, and you are done. This exact method has a proper name, the monotone chain algorithm, and it is the cleanest way to code convex hull in an interview.

The family resemblance: every algorithm on this page, from meeting rooms to rubber bands, is really the same two moves wearing a different costume: sort the input in a way that makes the answer easy to see, then walk through it once, only ever looking at what is right next to you.
NEIGHBORS ONLY

Line segment intersection sweep

Sweep a vertical line across all segments, keep the ones it currently touches sorted top to bottom, and only test neighbors in that order for a cross. A crossing swaps their order and creates a new event.

Sort key: segment endpoints, left to right  |  Used for: detecting any crossing, counting all crossings
NARROW STRIP

Closest pair of points sweep

Sort points by x. Sweep left to right holding the best distance d found so far. Only compare a new point against others within a strip of width d, and even then only a handful of nearby ones in y order.

Sort key: x coordinate  |  Used for: nearest neighbor style questions, collision checks
RUBBER BAND

Convex hull, monotone chain

Sort points left to right. Build the lower half of the hull by walking through and popping any point that creates a right turn. Repeat backwards for the upper half. Glue both halves into one loop.

Sort key: x coordinate, then y  |  Used for: smallest enclosing shape, outer boundary questions
