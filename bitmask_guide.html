Welcome to Bit City 💡

Bit manipulation is just light switches. That's it. A number is a row of switches: 1 = ON, 0 = OFF. Every operation below is just "which switches do we flip, and how?"

🎛️ The Switchboard (click the bits!)

Each switch has an index (top, counted from the right, starting at 0) and a value (bottom). The number = sum of values of all ON switches.

🧠 Golden rule #1: Index 0 is the rightmost bit (the humble doorman 🚪). Almost every bug beginners make is reading the indices from the left.

🧪 The 5-step dry-run recipe

Use this for every problem in the Arena below. Do it on paper:

  1. Write each number in binary, aligned, with index labels on top (0 on the right).
  2. Build the mask on its own line (for example 1 << k).
  3. Apply the operator column by column, never "as a whole".
  4. Read the result row back as decimal.
  5. Sanity-check with a tiny case (like n = 1 or n = 0).

Chapter 1: Reading the switchboard 📖

Place values double as you go left: 1, 2, 4, 8, 16, 32, 64, 128 …

⭐ The most important number in bit-land: 1 << k. It is a number with only switch k ON, I call it the spotlight 🔦. Its value is 2k.

Mini examples

  • 13 = 8 + 4 + 1 → switches 3, 2, 0 are ON → 00001101
  • 40 = 32 + 8 → switches 5 and 3 → 00101000
  • Even numbers always have switch 0 OFF; odd numbers always have it ON. (That is why n & 1 tells odd/even.)

Chapter 2: The six residents of Bit City 🏘️

Each one has a personality. Learn the personality, forget memorising.

🚪

AND &: the Bouncer

Lets a bit through only if BOTH numbers have a 1 there.
Use it to: check a bit, clear bits, keep only some bits.

🎉

OR |: the Party Host

Bit is 1 if EITHER has a 1.
Use it to: turn bits ON, merge sets.

🕵️

XOR ^: the Spy

Bit is 1 if the two bits are DIFFERENT. Same bits cancel to 0.
Use it to: toggle bits, find the odd one out, swap.

🙃

NOT ~: Opposite Day

Flips every bit (0↔1). In Java, ~n = -n - 1.
Use it to: build "everything except" masks.

🛗

Left shift <<: Elevator Up

Slides all bits left, fills 0s on the right. n << k = n × 2k.

🛗

Right shift >> / >>>: Elevator Down

n >> k = floor(n / 2k), keeps the sign. >>> (Java) fills 0s no matter what.

🧠 Cheat phrases: AND = "both or nothing". OR = "at least one". XOR = "exactly one" (or "are they different?").
Useful facts: x & 0 = 0, x & 1 = x, x | 0 = x, x ^ 0 = x, x ^ x = 0.

Chapter 4: Mask recipes 🎭

A mask is a tiny stencil. Build the stencil, then use & | ^ with it. Examples below use the shown k, l, r.

⭐ Why (1 << k) - 1 works: 1<<k is a lone 1 followed by k zeros (like 1000). Subtracting 1 turns that lone 1 into 0 and all the zeros below it into 1s (0111). Instant "k ones" mask!

Chapter 5: Wizard tricks 🧙

The famous one-liners. Each has a visual so you can see why it works.

🪄 1. n & (n-1): the Lowest-1 Eraser

Subtracting 1 flips the lowest 1 to 0 and turns all zeros to its right into 1s. AND-ing with the original wipes that whole zone. Result: lowest set bit erased.

  • Power of two? → n > 0 && (n & (n-1)) == 0 (a power of two has exactly one 1, erase it and nothing is left)
  • Count set bits (Kernighan): while(n > 0){ n &= n-1; count++; } runs once per 1, not once per bit

🪄 2. n & -n: the Lowest-1 Spotlight

Negative numbers are stored as two's complement: -n = ~n + 1. Flip everything then add 1; the carry ripples up through the zeros and stops right at the lowest 1, leaving only that bit in common.

Used in: Fenwick trees (BIT), iterating set bits of a mask, finding the lowest set bit's value.

🪄 3. XOR superpowers 🕵️

  • a ^ a = 0 (twins cancel), a ^ 0 = a, and order doesn't matter.
  • Single number: XOR the whole array; every pair cancels, the loner survives.
  • Missing number in 0..n: XOR all indices and all values, the missing one is left.
  • Swap without temp: a ^= b; b ^= a; a ^= b;
  • Do they differ? a ^ b has a 1 exactly where they differ. Hamming distance = Integer.bitCount(a ^ b)

Chapter 6: Bitmask = a tiny set 🧺

Have at most ~20–30 items? One integer can store "which items are picked". Bit i ON = item i is in the set. This powers subset enumeration and bitmask DP.

// 1) all subsets of n items
for (int m = 0; m < (1 << n); m++) { /* m is one subset */ }

// 2) walk over the set bits of m (fast)
for (int t = m; t > 0; t &= t - 1) {
    int i = Integer.numberOfTrailingZeros(t);   // item i is in m
}

// 3) all submasks of m (including m and 0)
for (int s = m; ; s = (s - 1) & m) {
    /* use s */
    if (s == 0) break;
}

Submask walk for m = 13 (01101 = {A, C, D})

🧠 Why (s-1) & m works: subtracting 1 gives the "previous" number, AND-ing with m throws away bits that aren't allowed. You land on the next smaller submask, in order, with nothing skipped.

Chapter 7: Traps in Java 🪤

1. Shift count wraps. For int, the shift amount is taken mod 32: 1 << 32 == 1, and 1 << 31 is negative (-2147483648). For 31+ bits use 1L << k and a long mask.
2. >> vs >>>. -8 >> 1 = -4 (sign bit copied), but -8 >>> 1 = 2147483644 (zeros fill in).
3. Precedence bites. Order high→low: ~, + -, << >>, < >, == !=, &, ^, |. So 1 + 2 << 3 is (1+2) << 3 = 24, and n & 1 == 0 is parsed as n & (1 == 0) (compile error). Always parenthesise: (n & 1) == 0.
4. Odd check with negatives. -3 % 2 == -1, so n % 2 == 1 misses negative odds. (n & 1) == 1 always works.
5. Forgetting that ~ flips all 32 bits. ~5 is -6, not 2. To flip only the lowest 3 bits use n ^ 7, not ~n.
